# LLM 术语表：中文用法与英文来源

遇到一个陌生词时，先找到它在当前问题中的含义，再决定是否需要补课。下面的词条给出简短定义、先修概念、
容易混淆的概念，以及进一步讲解和实践的入口。

## 先判断它是不是需要背的术语 { #usage-status }

这张表记录的是**本项目的中文用词建议**，不是国家标准，也不是对整个中文行业做过频率统计后的结论。2026-09-20
的审校覆盖了站点中除历史证据台账外的读者页面，逐条复核原有 262 个词条，并补入 37 个正文高频概念。判断时同时参考中文技术资料中的实际用法和
英文论文、规范或官方文档中的原始含义；英文链接主要帮助核对概念来源，不能单独证明某个中文译名有多流行。
中文写法还交叉参考了 [Google 机器学习术语表](https://developers.google.com/machine-learning/glossary?hl=zh-cn)、
[Microsoft Learn 机器学习术语表](https://learn.microsoft.com/zh-cn/dotnet/machine-learning/resources/glossary)和
[Hugging Face 中文文档](https://huggingface.co/docs/transformers/zh/index)。这些资料之间若没有一致译名，词条会标成
“多译并存”或“英文/缩写为主”，而不会为了表面整齐强行造词。

术语源自英文，不等于它是错误直译。“注意力”“微调”“向量数据库”等译名已经进入中文技术交流。若某个说法只是把
几个普通词临时组合起来，表中不会为了提醒读者而反过来把它收录成正式词条；正文会直接说明具体动作。

| 中文用法 | 阅读时怎样理解 |
|---|---|
| 中文通行 | 中文译名稳定且常见，可以直接使用；第一次出现时仍给英文，方便继续检索。 |
| 中英并用 | 中文和英文都常见；正文优先选更顺口的一种，并在首次出现时并列。 |
| 英文/缩写为主 | 业界通常直接说英文、缩写、算法名或协议名；中文只负责解释，不另造一个需要背的名字。 |
| 多译并存 | 能找到多种合理译法，没有必要把其中一种说成唯一标准。 |
| 讲解性表达 | 这是为了说明当前工程问题而组织的说法，不应包装成公认的独立术语。 |
| 不建议作术语 | 组合方式容易让普通要求看起来像正式算法名；正文应拆开说明实际动作。 |

表中有稳定中文译名时，使用“中文（英文）”；算法名、协议名和缩写则保留英文在前。反引号只用于代码、字段和值，
不用于把普通英文名词伪装成代码。协议确实把某个字段命名为 `artifact`、`schema` 或 `revision` 时，字段保持原样，
旁边再解释为“产物”“结构约束”或“版本标识”。

查到词条后，先读“核心定义”。定义里仍有不懂的概念，就沿“先修”回补；再用“易混淆”检查自己是否把两件事当成了
同一件事。需要完整学习顺序时，打开[概念依赖与易混淆地图](concept-map.md)。

最后一列区分实际实验与验证思路。有些主题已有运行命令，有些只有实验设计；进入目标页后，先确认输入、预期观察和
当前证据范围。同一词在不同框架中可能有不同定义，应以对应正文和固定版本为准。

1. 先看“中文用法”：标成“英文/缩写为主”或“讲解性表达”的词，不必硬背一个中文名。
2. 从“先修”列逆向回补，不需要把整张表从头背到尾。
3. 能用自己的话解释“易混淆”列中的区别，才算掌握当前术语。
4. 阅读正文后运行验证入口，记录观察和失败边界；命令跑通不等于方法有效。
5. 面试复习时先说问题、机制和适用边界，最后再说术语名称。
