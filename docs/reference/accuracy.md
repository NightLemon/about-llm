# 内容准确性与核验台账

本页定义教材中的事实如何分类、验证和维护。目标不是用“官方”二字替代证据，而是让读者知道每条结论在什么边界内成立、仓库实际验证了什么、哪些仍需目标环境实测。

## 四类陈述与证据

| 类别 | 典型内容 | 首选证据 | 必须写清的边界 |
|---|---|---|---|
| 数学与算法 | attention 公式、复杂度、KV Cache 容量 | 推导、可执行小例子、单元测试 | 变量定义、单位、假设和省略项 |
| 代码与 API | 请求字段、chat template、CLI 参数 | 固定版本官方文档、schema、契约测试 | provider、API/runtime 版本、`checked_at` |
| 产品事实 | 模型能力、配额、价格、区域和数据政策 | 对应产品的官方页面 | 检查日期；不得把当前状态写成永久事实 |
| 工程估算 | 显存、吞吐、延迟和成本 | 明确公式加目标环境基准 | 硬件、dtype、batch、长度、并发、软件版本和误差来源 |

论文能说明论文中的方法，不能自动证明某个当前闭源产品采用相同内部实现。官方文档能证明文档在检查时给出的接口承诺，也不等于本仓库已经在真实账号、网络、GPU 或付费端点上运行成功。

## 核验边界

- 离线单元测试证明给定输入下的本地实现行为，不证明云端 API 当前可用。
- CPU smoke test 不证明 CUDA kernel、vLLM、bitsandbytes 或目标 GPU 的兼容性与峰值显存。
- 一台机器上的 benchmark 只对记录的 workload 和版本有效，不是普适性能排名。
- JSON mode 只保证产生有效 JSON；OpenAI Structured Outputs 在受支持范围内约束 JSON Schema，但两者都不保证内容真实、业务规则正确或工具调用已获授权。
- schema、引用格式和安全分类器通过，只是系统质量证据的一部分，不能替代语义评测与权限控制。

## 写作与实现规则

1. 未公开的闭源模型参数量、层数、训练数据、路由和后训练配方保持未知，不从旧论文或同品牌模型外推。
2. 开放权重模型的架构结论绑定 checkpoint revision，以实际 `config`、tokenizer、chat template、generation config、model card 和许可为准。
3. 时间敏感 API 或产品事实记录 `checked_at`；稳定教材不维护“永久 latest”模型、价格或上下文窗口表。
4. 数字示例写明单位、公式和排除项。容量估算与实测峰值分开，decimal GB 与 binary GiB 不混用。
5. 性能结论绑定硬件、dtype/量化、输入输出长度分布、batch/并发、runtime/kernel 版本和采样参数。
6. OpenAI-compatible 只表示部分请求形状兼容；provider 的扩展字段、错误、usage、流式事件和工具语义分别验证。
7. 工具调用是模型提出的候选动作，不是授权。参数校验、身份、权限、幂等和审计由外部 runtime 承担。

## 已有可执行证据

- NumPy correctness oracle 覆盖稳定 softmax、past-aware causal mask、fully-masked-row 拒绝、RMSNorm、RoPE、GQA 与 cache/full causal 等价；PyTorch/JAX tiny GPT 分别覆盖模型级因果性、前向/训练等路径。仓库没有声称三套完整模型逐层/逐梯度等价，也没有目标 GPU kernel 的精度或性能证据。
- Decoder config inspector 对 strict local JSON object 做 canonical semantic fingerprint，报告显式 core/MoE/MLA marker，并只在 standard attention 字段完整、自洽且没有已知 MLA marker 时计算理想 dense K/V payload。Authored GQA fixture 在 32 层、8 KV heads、head dim 128、4096 tokens、batch 1、2-byte element 下精确为 536,870,912 bytes；authored MoE-GQA fixture 在 24 层、4 KV heads、head dim 128、同 token、batch 2 下为 402,653,184 bytes；authored MLA/MoE fixture 必须拒绝标准估算。测试另覆盖 MHA/MQA 分类、duplicate/nonfinite/non-object/非法 UTF-8 JSON、bool/负数/不整除/缺字段、nested snapshot、standard/MLA CLI round trip 与 Base/Instruct tokenizer mock。真实 checkpoint 脚本检查的是 `AutoConfig.to_dict()` normalized snapshot，可能含库默认值/metadata，其 fingerprint 不是 raw `config.json` byte hash。三个 fixture 不属于 Llama/Qwen/DeepSeek；marker 列表并不完备，fingerprint/unkeyed hash 与 resolved metadata 不认证来源或权重，也不证明参数量、有效上下文、实际 cache layout、显存、质量、许可或 runtime 支持。
- Generation-protocol inspector 对 strict combined JSON 做 canonical identity，把 tokenizer/model config/generation config 的 BOS/EOS/PAD/decoder-start 归一成集合并逐对报告 exact/subset/superset/overlap/disjoint，同时检查 tokenizer size/model vocab 越界。Authored aligned fixture 固定 `{2}` 对 generation EOS `{2,3}` 的 strict-subset，而 drift fixture 固定 BOS/EOS/PAD disjoint 且 PAD 9 越过两侧 8-token 上界；测试覆盖缺 generation config、PAD=EOS neutral observation、双 length field、duplicate/negative/bool/empty ID、schema/UTF-8、nested snapshot、CLI 与 checkpoint mock。它不裁决哪一方正确，不解析 `generate()` kwargs、模型 fallback、runtime precedence 或 stop-string tokenization；normalized `to_dict()` 不是 raw file hash，静态 match/mismatch 都不证明 Transformers/vLLM/provider 的有效停止行为、权重、来源、质量或许可。
- Transformers generation runtime control 在 3,824-parameter 随机 tiny GPT-2 上真实执行 forward、LogitsProcessor 与 GenerationMixin stopping loop；authored processor 把每步全部 scores 覆盖为一个 token，固定得到 config EOS-set `[4,3]`、call EOS override `[3,5]` 与 call max-new-token cap `[4,6]`，并验证 caller GenerationConfig 未 mutation。测试覆盖三条 exact trace、重复运行 deterministic、processor 输入 gate 与 CLI。它没有真实 tokenizer/chat template或公开 checkpoint，权重不决定 token；finish reason 由已知 plan/条件推断而非框架返回，不证明正常 logits/processor 组合、vLLM/provider、GPU、质量、延迟或吞吐。
- Next-token sampling oracle 固定 sign-aware unique-token repetition → temperature → exact top-k（score tie 按 token id）→ post-top-k-normalized top-p（保留 crossing token）→ renormalization → token-id-order inverse CDF。固定 `[0.4,0.3,0.2,0.1]`、k=3、p=0.7、u=0.6 fixture 精确得到 `[4/7,3/7,0,0]` 并选 token 1；signed penalty fixture 将 `[2,-2,0.5]` 变为 `[1,-4,0.5]`。测试覆盖 threshold/tie/CDF、temperature-support、稳定性、平移不变性和失败输入。它没有模型/tokenizer、多 token/EOS/stop/KV/batch，也不证明 Transformers/vLLM/provider 默认、跨 RNG bitwise replay、质量或性能。
- Deterministic beam-search oracle 对 authored probability table 逐步展开全部正概率 token，active prefix 按 raw cumulative log probability、再按 token-id sequence 排序，EOS 立即进入 finished 且永不再次展开，达到 token cap 的 active prefix 标记 length。最终分数固定为 `log_probability / generated_length**length_penalty`，长度只计生成 token、包含 EOS、不含 prompt。固定 pruning fixture 中 beam 1 返回 `(A,EOS)` 概率 0.306，beam 2 返回 `(B,EOS)` 概率 0.4；length fixture 在 alpha 0/2 分别返回长度 2/3 的候选。测试覆盖 tie、EOS terminal、零质量 token、final ranking、严格输入和脚本 scope。它保存所有从 active prefix 产生的 EOS、不做 heuristic early stopping，不模拟特定 runtime 的 candidate cap，也没有模型/tokenizer/KV/GPU、质量或性能证据。
- Token-aware constrained-greedy oracle 把 authored finite literal set 编译成 Unicode-code-point trie，对每个 supplied token text 执行完整多字符转移，EOS 只在 accepting state 开放，并在 masking 后按 allowed raw mass 重归一化。JSON-like fixture 中高概率 0.65 的 `1]` 因第二个字符非法被屏蔽，`1}`/`2}` 的 0.25/0.10 质量由 0.35 归一化成 `5/7`/`2/7`，最终输出 `{"x":1}` + EOS。测试覆盖 Unicode token、首字符反例、zero-mass typed dead end、EOS/length/acceptance 分账、tie、不可变输入和严格契约。它假设 supplied fragments 直接拼成文本，只接受有限字符串集合；不执行 tokenizer byte state/normalization、JSON Schema/CFG、模型/KV/GPU，也不证明 provider 等价、语义正确、质量或性能。
- Incremental stop matcher 对 arbitrary UTF-8 bytes 做 strict atomic decode，逐 character 检查 first completion，最长 partial stop prefix 留在 bounded pending，同一 character 多 stop 按配置顺序。固定 `甲🙂乙<END>尾` fixture 跨 emoji/stop bytes 只返回 `甲🙂乙`、匹配 `<END>`、丢弃尾字符；`("BC","ABC")`/`ABCZ` 选择 `BC`、返回 `A`。测试覆盖 include/exclude、disproof/EOF flush、chunk invariance、overlap、invalid/truncated UTF-8、normalization/case 与 terminal state。它不解模型 token，不证明 provider finish reason/usage、server cancellation、KV/GPU release 或计费停止。
- MoE routing oracle 对 finite `[tokens,experts]` logits 执行 padding-aware stable softmax、expert-id top-k tie-break、`ceil(capacity_factor*N*k/E)` per-expert capacity、score/token/rank priority、assignment keep/drop 与可选 post-drop renormalization，并用 kept assignment 真实执行 bias-free linear expert combine。固定 `N=4,E=3,k=2,factor=0.75` fixture 的 capacity=2，counts 从 `(3,4,1)` 变为 `(2,2,1)`，8 个 assignment 保留 5、丢 3、整 token drop 为 0；另验证 uniform balance/z-loss/entropy、padding、整 token drop、不可变数组和失败输入。`E*sum(f_e*p_e)` 是仓库广义诊断而非通用 aux loss；该 CPU toy 没有训练 router/MLP、backward、all-to-all/GPU、目标 checkpoint、质量或性能证据。
- Activation patching reference 在 seeded random MiniGPT 上实际缓存 layer-0 post-residual tensor 并执行 forward-hook patch；固定 fixture 验证 joint visible-prefix recovery=1、future-position control=0、hook 移除、严格 shape/device/token 契约、不裁剪 recovery 和小分母拒绝。模型未训练、batch=1，token pair 按当前 clean-corrupt contrast 事后选择；它证明 tensor intervention 与 causal negative control，不证明目标 checkpoint 的语言行为、自然/唯一 circuit 或跨样本稳定性。
- Continual-learning reference 对严格方阵解析计算 final ACC、BWT、非负 peak-to-final forgetting 与相对 pretraining baseline 的 FWT，并拒绝单任务、非方阵、非有限或越界 accuracy；uniform reservoir 有独立边界/确定性测试。PyTorch benchmark 实际执行两阶段 SGD 和 seed 0–19 的 no/64-example/full replay：有限 buffer 对旧任务 accuracy 的 paired mean gain 为 0.4758，95% seed-level interval [0.3389, 0.6104]，同时新任务差值为 -0.0072 [-0.0102, -0.0045]。它是带显式 task-id、固定 task/data、optimizer-step-matched 但非 compute-matched 的 synthetic control；区间不覆盖任务/数据不确定性，也不证明目标 LLM、安全 retention、隐私成本或 replay 总有效。
- KV Cache 理想化 dense K/V 公式由 `estimate_kv_cache_bytes` 实现；32 层、8 KV heads、head dim 128、8192 tokens、BF16 的结果精确为 1 GiB，测试同时验证 batch 缩放与非法维度。
- Paged KV metadata allocator 测试覆盖固定 block partition、sequence block table、prefix fork/refcount、shared partial-tail COW、shared full-tail append、释放/确定性复用，以及 exclusive/shared tail 无容量时 mutation 前原子失败。toy 的 3×4-slot fixture 验证 `4+2` fork、COW、物理碎片和 release。`logical_tokens` 按序列重复共享 prefix，`physical_token_values` 才用于 allocated-slot fragmentation。它不存储/复制真实 K/V，不覆盖 GPU page table/PagedAttention、并发 kernel、prefix identity/ACL、eviction/preemption/swap、metadata bytes、VRAM 或性能。
- Prefix-cache metadata oracle 要求 trusted tenant/visibility domain、authorization/policy、model/tokenizer/chat-template/adapter、position/RoPE config、KV dtype 与 exact token prefix 全部匹配，并选择最长项。固定 fixture 将所有 fingerprint 强制碰撞，仍精确得到本 tenant 长度 3 hit、未存 tenant miss、1/1 hit/miss 与 release 后 0 active lease；测试另逐字段验证隔离、leased entry pin、unleased LRU、全 leased no-mutation capacity failure 和 foreign/double release。Fingerprint 只作候选索引；它不授权、不保密，也没有真实 K/V、TTL/加密/分布式一致性、timing-channel mitigation、vLLM 等价、VRAM、命中率、prefill savings 或性能证据。
- Continuous-batching reference 在整数 boundary 上执行固定 FCFS admission、decode-first、chunked-prefill policy，并以 `max_batch_tokens >= max_running_sequences` 保证 resident request 每轮进展。固定三请求 fixture 的逐轮 used slots 为 `3,3,2,2`；7 个 prompt、6 个 output、3 个 request 得到 `7+6-3=10` 个 causal forward positions，验证 prefill 最后位置发出首 token、sequence-cap queue、TTFT/TPOT step、completion、idle/active capacity 与确定性。它没有执行模型/KV/GPU，也不覆盖 prefix cache、preemption、priority 或真实时间，不能证明 vLLM scheduler equivalence、wall-clock latency/throughput、GPU utilization 或 SLO。
- KV-aware batching reference 把同一 boundary 语义接入 `PagedKVAllocator`；block 不足时只能抢占本轮尚未工作且 stable-FCFS 优先级更低的 resident，再选择最近 admission 者，单向优先级边与 repeated-state guard 防止 rebuild ping-pong。被抢占请求释放 metadata KV，按 FCFS 再 admission 后只重建旧 logical context，不重复输出。3×2-slot、A=`P4/O3`、B=`P2/O2` fixture 的 used slots 为 `3,3,1,1,2,1`，logical/recomputed/executed positions 为 `9/2/11`，B 的 emission boundary 为 `2,6`，preemption=1、peak/final allocated blocks=3/0；6-block 对照无抢占且 logical=executed=9。它不存 K/V 数值，不覆盖 swap/prefix reuse/priority aging/CUDA/分布式或墙钟，也不证明 vLLM equivalence、VRAM、性能或质量。
- Weight-only quantization reference 对 contiguous row group 执行 finite FP32 symmetric absmax、`[-qmax,qmax]` code、全零 group scale=1、offset-binary LSB-first dense bit packing、canonical padding/unused-code 拒绝、strict v1 little-endian 单矩阵 artifact、exact reload、反量化和 NumPy linear output。固定 3×5、4-bit、group-size 4 fixture 为 FP32 60 bytes、实际 code 8 bytes（4 个 padding bit）、scale 24 bytes、raw payload 32 bytes、32-byte header + trailing SHA-256 后文件 96 bytes；2–8 bit 跨 byte 测试均 round-trip。测试另拒绝错误 version、payload/digest tamper、trailing/truncation、NaN scale 和覆盖已有输出。Unkeyed digest 不认证来源，单矩阵 artifact 也不是完整模型、fused low-bit kernel、calibration/GPTQ/AWQ、目标质量、显存或延迟证据。
- Multi-matrix quantized bundle reference 把多个 name-sorted、完整 v1 矩阵 artifact 放入 24-byte header + canonical JSON manifest + contiguous payload + 32-byte outer SHA-256，绑定 model/tokenizer revision、architecture config identity，以及每个 tensor 的格式版本、offset、length 和 digest。默认 seed=29、4-bit、group-size=4 two-layer fixture 固定为 FP32 weights 288 bytes、raw payload 124 bytes、inner artifacts 252 bytes、manifest 679 bytes、bundle 987 bytes、outer container overhead 735 bytes；严格 reload 后 byte 与 quantized-forward round trip 为 true，FP32-output RMSE 约 0.0368725、relative L2 约 0.123272。测试拒绝 duplicate/unknown/non-canonical manifest、name/order/offset/digest 漂移、trailing/truncation 和资源上限外输入。它只有 tokenizer identity、没有 tokenizer payload，也不支持未量化 state、model forward、shard/GGUF/safetensors/runtime layout 或 fused kernel；两层 NumPy control 不证明完整 LLM checkpoint、来源认证、质量、VRAM 或加速。Exclusive-create + file fsync 不证明 crash 后无 partial target、parent-directory durability 或断电原子发布。
- Repo-native quantized MiniGPT inference checkpoint 保存 Byte-BPE merge payload、canonical config、固定 architecture revision、全部唯一参数和 tied LM-head contract；二维 embedding/linear 使用 v1 quantized matrix artifact，一维 norm/bias 使用 little-endian FP32，causal mask 由 loader 重建。默认 seed=7 fixture 有 16 个唯一参数、FP32 parameter bytes 10,976、manifest 3,904、payload 4,760、artifact 8,720；prompt `abc abc`→`[257,32,257]`，reload logits `[1,3,258]`，重复读取 exact，FP32-logit RMSE≈0.00477277。21 个测试另覆盖 bias-free two-layer/5-bit/non-divisible group、tokenizer/全部 state/tie/forward、runtime/config/mask drift、outer/inner tamper、duplicate/unknown/non-canonical JSON、name/shape/kind/order/offset/quantization/vocab/architecture drift、非有限 FP32 vector、资源上限、no-overwrite 与 handle release。完整性仅对 trusted repo MiniGPT inference loader 成立：forward code/base-byte algorithm 不嵌入，且无 normalizer/special/chat template、optimizer/RNG/training resume、shard/device/runtime layout、GGUF/safetensors/vLLM、low-bit execution、目标质量/VRAM/性能或来源认证证据。

- Strict JSON model planner 测试覆盖 tool/finish/escalate、duplicate/nested-duplicate key、`NaN/Infinity`/overflow float、Markdown fence、closed fields、unknown tool、evidence contract、deep-frozen tool schema、request state/budget/tool/prompt identity、model/finish-reason/output-cap/byte drift、recorded exact replay、provider metadata promotion和 deterministic decision identity。另有 16 个 executable schema 测试覆盖 explicit Draft 2020-12、closed root、valid/invalid schema、local/external reference、format annotation/enforcement、deep freeze、schema/instance byte cap、脱敏 JSON Pointer error、contract fingerprint 和 schema-before-resolver/policy/handler。端到端 control 由同一 contract 派生 Planner schema/runtime Tool，锁定 draft/schema/validator、两次 request/response/decision，运行 local parser→standard schema→resource/policy→simulated handler→exact verifier，并证明 request drift、fenced JSON、runtime `const` rejection 与 missing capability fail closed。两条 response、provider request id、62 tokens 与 0.03 cost 都是 authored fixture；schema 不 coercion/default/authorize，无网络/模型/provider 账单/生产 IAM/开放语义 verifier，SHA-256 也不认证来源、安全性或真实性。
- 云 API contract CLI 明确输出 `network_performed: false`，只证明固定 fixture 的字段映射、严格解析与密钥脱敏，不证明真实端点可用。
- 云 API retry matrix 只证明本地 `408/429/500/502/503/504` allowlist、bounded exponential backoff、严格 `Retry-After`、attempt/deadline 和 replay/outcome fail-closed 决策在固定输入下自洽。它不发送请求，也不证明真实 provider 当前错误语义、配额恢复、idempotency key、重复计费去重或 endpoint 可用；有效 `Retry-After` 超预算时停止而非提前重试。
- 云 API async executor 的 `httpx.MockTransport` 测试覆盖 exact origin、HTTPS/no-query/no-redirect、monotonic deadline、connect 与 outcome-uncertain timeout 分类、取消传播、strict object JSON 和脱敏 attempt trace。它不执行真实 DNS/TLS/proxy/证书/egress，也不证明 endpoint 或 provider 语义；非流式 `max_response_bytes` 在 body 缓冲后检查，不是 ingress/memory 上限。
- SSEDecoder 的 CPU byte fixture 覆盖 UTF-8/BOM、LF/CRLF/CR、多行 data、line/event/total byte gate 和截断 EOF；三类 cloud stream state 分别验证 `[DONE]`、`message_stop`、finishReason+EOF 及 text/usage/finish 顺序。它只证明 text-only framing/state，不执行 streaming HTTP，不支持 tool/thinking/media，不证明真实 provider event schema、backpressure、取消传播或停止计费。
- Cloud SSE executor 的 MockTransport/AsyncByteStream 测试覆盖 pre-body HTTP retry、`text/event-stream`、增量 callback、idle/overall deadline，以及成功/截断/超限/timeout/cancel 的 response close；2xx body 开始后不重试。它不证明真实 TCP/HTTP2/backpressure、服务端观察取消或停止计费；partial callback 文本不可撤回，`bytes_received` 也不是 token/wire-byte 指标。
- Cloud usage budget reference 从 OpenAI-compatible/Anthropic `max_tokens` 或 Gemini `generationConfig.maxOutputTokens` 提取唯一正整数 cap，从恰好一个 body/URL 来源提取 model 并要求与 pricing snapshot 精确相等；identity version、billing scope、URL、body 与规范化 header 绑定为 SHA-256 request fingerprint。常见 credential 值先替换，测试证明同 scope key rotation 稳定、prompt/cap/scope drift 改变 identity；settle/cancel/uncertain 错 fingerprint 不释放 active reservation。显式 provider/model/revision/checked_at pricing snapshot 下，以整数 micro-USD per million tokens 对 input estimate + cap 做原子 reservation，成功按 reported usage settle，确定未发送才 cancel，usage 不确定则提交完整 reservation。固定 `$1/M + $2/M` fixture 得到 60+10 预留 80 micro-USD、58+4 结算 66 micro-USD；两线程不重复占用 cap，post-call overrun 先入账再阻断。内存版不验证 tokenizer estimate、provider 字符串/endpoint 与费率归属、caller/pricing/transport、provider usage/隐藏或 cached/reasoning token；hash 不是签名/保密，也不是发票、持久 ledger、HTTP 原子事务或 billing reconciliation 证据。
- MinHash/LSH reference 以 SHA-256 stable shingle mapping、seed-derived affine hash、完整 band tuple collision 生成 deterministic lexical candidates，并绑定 item/report fingerprint；所有候选可 exact Jaccard recheck。默认 authored toy 的 5 items/10 pairs 得到 3 candidates，其中 threshold 0.8 下 1 true positive、2 false positive，exhaustive snapshot recall=1、precision=1/3；测试另锁定 1-hash 配置漏掉 Jaccard=2/3 pair 的 recall=0 反例。理想 `1-(1-s^r)^b` 只在独立 MinHash 模型下描述候选概率，不保证单 pair 或新数据召回；exhaustive recall audit 仍为 \(O(N^2)\)。该实现不证明 semantic/translation duplicate、真实域阈值、hash authenticity、数据许可或 readiness 可直接改用近似 pass。
- SQLite usage budget reference 把 pricing+limits singleton config、reservation tombstone 与 event timeline 放入本地数据库，并以 `BEGIN IMMEDIATE` 串行化写事务。测试证明同一文件的两连接不会重复预留最后容量、子进程退出后 active 仍占额度、配置漂移 fail closed、event trigger failure 整笔回滚、文件句柄释放，以及 post-call overrun 先持久化再报错；离线 demo 重开后把 active 记为 uncertain。它只证明 local durable atomic quota：active 不按 TTL 自动释放，无密钥 config/request fingerprint 不抗协同篡改；不与远程调用原子，不认证 pricing/provider usage/invoice，不证明断电/备份恢复、跨机器/跨区域 quota、服务端取消或 exactly-once billing。
- Budgeted cloud HTTP reference 在 target preflight 后才 reserve，并强制 `max_attempts=1`；测试覆盖完整 usage settle、ConnectError cancel、HTTP 500 uncertain、2xx 缺 usage/malformed uncertain、task cancellation uncertain、retry/错误 origin 在 transport 前拒绝，以及 SQLite uncertain 重开。MockTransport demo 得到 settled 66 + uncertain 80 = committed 146 micro-USD。它只证明本地单-attempt 控制流；结构化 pre-send failure 才能证明未发送，HTTP status 的 outcome known 不等于零计费。它不执行网络，不解析 provider-specific error usage，也不消除 provider effect 与 SQLite commit 的 crash window；生产 replay 必须逐 attempt 独立 reserve，不能由一次逻辑-call cap 覆盖。
- JAX/Optax tiny-batch 实验在输出中记录实际 backend/device 并同步计时；当前只证明 CPU 小模型闭环，不证明 GPU/TPU 或多设备 sharding。

## 尚未由本仓库证明

- 当前机器没有完成真实 CUDA/vLLM/QLoRA 的目标硬件验证；文档中的命令是运行路线，不是成功声明。
- 离线 adapter 测试没有访问 OpenAI、Anthropic、Gemini、DeepSeek 或 Qwen 的真实付费端点，也不证明账号配额、区域或最新产品行为。
- 任何吞吐、TTFT、TPOT、显存与费用结果都需要在目标环境保存 workload manifest 后才能成为可比较证据。
- 闭源模型未公开的内部架构与训练配方不在可核验范围内。

## 维护流程

1. 修改公式、API 或数字前先确定陈述类别与证据等级。
2. API/产品事实优先核对固定版本官方文档，记录 provider、版本和 `checked_at`。
3. 将能执行的不变量写成最小测试；不能执行的事实明确标注“文档核对”或“待目标环境验证”。
4. 运行 `python scripts/check_content_accuracy.py`，再运行完整测试、严格类型检查和 MkDocs strict build。
5. 目标环境基准保存原始结果、配置、硬件与软件版本；只在这些条件内解读结论。
6. 发现勘误时更新正文、测试、台账与 `CHANGELOG.md`，避免只改其中一处。
