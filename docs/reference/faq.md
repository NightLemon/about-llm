# 常见问题

这里给出判断问题的起点，不把短答当成部署承诺。需要沿概念补前置知识时查[概念依赖地图](concept-map.md)，需要选择第一次阅读或运行时回到[学习路径](../guide/learning-paths.md)和[实验与项目](../practice/labs.md)。

## LLM 到底是在记忆，还是在推理？

两者不是排他的简单二分。模型参数会压缩/记住训练模式和部分具体序列，前向计算又能组合上下文执行未逐字见过的任务。判断某能力来源需要反事实、污染检测、机制和泛化实验，不能凭答案风格。可从[预训练](../training/pretraining.md)和[评测方法](../quality/evaluation-methodology.md)继续核对。

## 模型有意识或理解吗？

“理解”和“意识”有多种哲学与操作定义。现有行为证据能证明模型在许多任务上形成有用表示并表现出泛化，不能仅凭流畅语言证明主观体验。工程上应围绕可测行为与风险，不把拟人化当机制解释。

## 参数越多越好吗？

同一高质量训练范式下，规模常带来收益；实际还由数据、训练 token、架构、后训练、推理预算和任务决定。小型专用模型可能在延迟、隐私和成本约束下更优。

## 上下文窗口和最大输出 token 是一回事吗？

不是。上下文窗口通常限制输入加已生成 token 的总量；最大输出是本次允许生成的上限。具体 API 可能还有独立限制。

## Temperature=0 就完全确定吗？

不保证。它通常表示 greedy，但浮点归约、并发批处理、服务版本和 tie-breaking 仍可能不同。记录模型版本、请求、采样设置和执行环境后，才可以为一个指定运行条件复现或排查差异；具体采样顺序见[生成与解码](../core/generation.md)。

## 为什么模型会幻觉？

语言模型目标是生成条件分布下可能的 token，不是从可信数据库返回验证事实。知识不完整、提示歧义、证据缺失、采样和训练偏差都会造成错误。用检索或工具提供证据、允许 abstain、验证关键主张并监控；再沿[RAG 生成](../applications/rag-generation.md)区分“有引用”和“论断被引用支持”。

## RAG 还是微调？

最新、私有或必须可引用的事实优先 RAG；稳定行为、格式、风格或领域模式可微调；复杂产品经常组合。先建立 Prompt 基线和评测集，再用错误类型选择。仓库的两条实现主线分别是[RAG Foundations](../practice/projects/rag-foundations.md)和[Single-GPU Finetuning](../practice/projects/single-gpu-finetuning.md)，它们只验证各自固定输入和边界。

## 向量数据库是 RAG 必需的吗？

不是。小数据可用内存索引；精确术语可用 BM25/数据库；结构化问题直接 SQL/知识图谱更合适。向量库是工具，不是架构目标。

## Agent 与工作流有什么区别？

工作流的分支和顺序主要由代码预定义；Agent 让模型在运行时选择下一动作。开放性越高，越需要预算、权限、审计、恢复和人工确认。确定任务优先工作流；从[一次退款任务](../applications/agent-task-lifecycle.md)可沿实际的 schema、ACL、审批与恢复路径阅读。

## 模型输出 JSON 就能直接执行吗？

不能。语法合法不代表字段真实、权限充足或业务条件满足。必须在执行层做 schema、范围、身份、ACL、当前状态、幂等与副作用校验。

## 能用 LLM 自动评测 LLM 吗？

可以用于规模化代理评价，但需用人类/程序可验证标签校准，并防位置、长度、自我偏好和提示敏感。高风险结论不能只凭单一 judge。

## 开源权重等于开源模型吗？

不一定。应分别检查权重许可、代码、训练数据、数据处理、训练配方和评测是否开放。“可下载权重”可能附用途或再分发限制。

## 本地模型一定更隐私吗？

数据不发给第三方是优势，但本地日志、恶意模型文件、依赖、共享显存、插件和运维仍可泄漏。隐私取决于完整数据流与控制，不只部署位置。

## 如何选择模型？

先定义目标质量、安全、语言、上下文、延迟、并发、数据驻留、许可和预算；在自己的版本化评测集与真实流量上比较每成功任务成本。公开榜单只用于筛选候选。把质量、尾延迟、失败分母与资源成本放在同一决策门中，见[评测总览](../quality/evaluation.md)和[模型选择](../models/landscape.md)。

## 学 LLM 必须有昂贵 GPU 吗？

不必。tokenization、注意力、检索、Prompt、评测和小模型训练可在 CPU、消费 GPU 或托管环境完成。大规模预训练需要集群，但理解原理不需要复制其规模。可从[环境配置](../guide/environment.md)选择本机条件下的入口；目标 GPU 的容量或速度结论仍须在该设备上测量。
