# NLP 与语言建模

## 文本不是天然的数字

自然语言处理首先要决定基本单位。传统方法使用字符、词、词干、n-gram 和稀疏词袋；神经模型使用稠密 Embedding；现代 LLM 多使用子词或字节级 token。每种单位都在词表大小、序列长度、未知词、多语言公平性之间权衡。

词袋忽略顺序，n-gram 只保留局部顺序。分布假设“一个词的意义由它出现的上下文体现”推动了词向量和上下文化表示，但语料相关性不等于真实世界语义。

## 语言模型

语言模型为序列分配概率。常见训练范式：

- **自回归/因果语言模型**：预测下一个 token，只能看左侧上下文。适合开放式生成。
- **掩码语言模型**：预测被遮住的 token，可双向看上下文。适合理解与表示学习。
- **前缀/序列到序列模型**：编码输入，再自回归生成输出。适合翻译、摘要等条件生成。

自回归目标：

\[
\mathcal{L}=-\sum_{t=1}^{T}\log p_\theta(x_t\mid x_{<t})
\]

训练通常采用 teacher forcing：预测第 \(t\) 个 token 时输入真实历史；推理时输入模型自己的历史，因此错误可能累积，这叫 exposure bias。

## 从概率到能力

“预测下一个 token”看起来简单，但要在多样文本上降低损失，模型必须压缩大量关于语法、风格、事实共现、代码结构和任务格式的统计规律。能力不是显式数据库表，而是分布在参数与运行时激活中的模式。

这也解释了边界：

- 目标奖励“像训练文本”，不直接保证真实、无害或符合用户意图。
- 稀有、更新快或互相冲突的事实难以稳定存入参数。
- 训练语料中的偏见、错误和模板会被学习。
- 生成是条件分布采样，相似提示可能得到不同答案。

## 上下文与歧义

上下文窗口限制模型一次可直接处理的 token 数。窗口更长不等于每处信息被同等利用；位置、干扰文本、检索质量和注意力模式都会影响效果。“针在干草堆”测试只是长上下文能力的一部分，不能代表多跳整合、全局一致性和长程生成。

语言天然含歧义、隐含前提和语用信息。高质量系统需要明确用户目标、请求缺失信息、保留不确定性，不能只追求一条流畅答案。

## 传统 NLP 仍然有用

正则表达式、词典、有限状态机、BM25、CRF 和小型分类器在确定性、可解释性、成本与延迟方面常优于 LLM。生产系统通常混合使用：规则做硬约束，检索提供证据，小模型路由，大模型处理开放语义。
