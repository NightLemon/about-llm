# 架构谱系与可解释性

## 架构不是只有 decoder-only

### Encoder-only

每个 token 可双向关注整段输入，输出上下文化表示，代表任务是分类、检索、序列标注和抽取。掩码语言建模适合学习表示，但不能直接按标准方式开放式左到右生成。

### Decoder-only

因果 mask 让位置只能看过去，用统一续写接口完成对话、代码和条件生成。Prompt 与输出在一个序列内，部署简单，成为通用生成模型主流。缺点是输入表示计算和生成耦合，长输入的双向理解未被架构显式利用。

### Encoder-decoder

编码器双向处理输入，解码器通过 cross-attention 读取编码结果并自回归生成。输入只编码一次，天然区分来源和目标，适合翻译、摘要等 seq2seq；服务需维护两套模块。

### Prefix/混合注意力

前缀部分双向可见，生成部分保持因果；也可在层间混合局部/全局注意力、卷积或状态空间模块。架构选择应以质量、长度、吞吐、训练稳定和内核成熟度比较，不能只看渐近复杂度。

## 状态空间与递归模型

SSM 用隐状态递推概括过去，理论上可线性扫描并支持流式推理。现代选择性 SSM 让输入控制状态更新，增强内容依赖。优势可能包括长序列和固定状态内存；挑战包括精确检索、并行训练实现、状态容量和生态成熟度。混合模型常用注意力负责精确关联、SSM/卷积负责高效局部或长程混合。

## 模型内部“知识”在哪里

Embedding、注意力、MLP 和残差流共同承载表示。事实或能力通常分布在多个参数和激活中，不是一个神经元对应一条知识。层、头或神经元可能具有选择性，但相关性不证明因果，也不保证跨 prompt/模型稳定。

## 可解释性方法

### 行为与探针

构造最小对比输入观察输出/隐藏状态；线性 probe 测某信息能否从表示中读出。Probe 成功只说明信息可解码，不说明模型用它做决策；强 probe 甚至可能自己学会任务。

### 归因

梯度、Integrated Gradients、遮蔽、SHAP 类方法估计输入或组件对输出的贡献。结果依基线、目标 logit、相关特征和非线性，注意力图也不是天然解释。用多方法、稳定性和反事实校验。

### 因果干预

消融头/层、activation patching、causal tracing 和路径 patching，通过替换/阻断激活观察输出变化。比纯相关证据更强，但干预可能离开正常分布，且冗余回路会掩盖贡献。

### Mechanistic interpretability

尝试把计算分解为可理解的特征与回路。常见概念：

- superposition：有限维度复用表示更多特征；
- polysemantic neuron：单个神经元响应多个无关概念；
- sparse autoencoder：把稠密激活分解成大量稀疏特征；
- circuit：多个组件协作完成特定计算的因果路径。

自动命名特征可能把复杂激活过度简化；稀疏性、重构误差和因果效力都需报告。

## 模型编辑

目标是局部修改事实或行为，包括定位后低秩更新、外部记忆和小规模继续训练。评价至少包含：目标更新成功、改写/多语言泛化、无关事实保持、相关知识一致性、持久性和副作用。修改一句回答不等于内部世界模型已全局一致更新。

## 可解释性不能替代评测

内部分析可发现机制和异常，但目前不能证明模型总体安全或真实。高风险部署仍需行为测试、访问控制、监控和治理。不要把漂亮的 attention 热图当作审计结论。

## 自测

1. Probe 能读出句法信息，为什么不能证明模型用它生成答案？
2. Activation patching 相比查看 attention 权重提供了什么更强证据？
3. 模型编辑的 locality 与 generalization 为什么可能冲突？
