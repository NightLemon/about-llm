# 规模化规律

## 三个主要尺度

模型效果受参数量 \(N\)、训练 token 数 \(D\) 和训练计算量 \(C\) 共同影响。对 dense Transformer，粗略训练 FLOPs 常写成 \(C\approx 6ND\)，只是用于预算的一阶近似；架构、序列长度、重计算和硬件利用率都会改变真实成本。

经验 scaling law 观察到损失对规模常近似幂律下降并趋向不可约损失：

\[
L(N,D)\approx L_\infty + aN^{-\alpha}+bD^{-\beta}
\]

指数和最优配比依数据、模型族、训练设置而变，不能把某篇论文的常数当作自然定律。

## Compute-optimal

给定训练算力，模型太大而数据太少会“训练不足”；模型太小而重复过多数据可能容量不足。compute-optimal 研究如何在 \(N\) 与 \(D\) 间分配预算以最小化训练损失。实际产品还要考虑推理成本：训练一个参数更小、token 更多的模型，可能比纯训练算力最优方案更适合长期服务。

## 涌现能力

某些能力在指标图上似乎跨过规模阈值后突然出现。需要谨慎：离散/非线性指标、题目难度、提示方式和采样噪声都可能把平滑概率改进显示成“突变”。这不否定质变现象，但要求用连续指标、更多尺度点和机制证据验证。

## 数据质量与重复

token 不等价。高质量、去重、任务相关、多样且许可清晰的数据可能比更多低质 token 有效。重复数据会改变梯度权重，提高记忆和隐私风险；多轮 epoch 也可能在数据受限时有用，但收益递减并依赖正则化与数据质量。

## 推理时规模化

能力不只由训练决定。增加输出 token、并行候选、搜索深度、验证器调用和工具使用，可用更多推理计算换质量。收益取决于：模型能否生成有用多样性、验证器能否识别正确结果、任务是否可分解，以及错误是否高度相关。

## 不要混淆的量

- 参数量 ≠ 激活参数量（MoE 每 token 只激活部分专家）。
- 训练 FLOPs ≠ 实际耗时（取决于硬件利用率和通信）。
- 上下文长度 ≠ 训练 token 总数。
- 模型规模 ≠ 系统质量（检索、工具、数据和评测会改变结果）。
- benchmark 分数 ≠ 真实世界效用。
