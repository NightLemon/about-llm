# ADR 0001：证据边界必须紧邻结论

- 状态：接受
- 日期：2026-08-28

## 背景

教材同时包含推导、固定样例、真实框架运行和外部产品事实。若只写“已验证”，读者无法判断证据究竟覆盖机制、集成、性能还是生产行为。

## 决策

每个重要 claim 都要标明实际观察对象、运行条件、证据入口和不可外推范围。固定结果与完整账本放在 `docs/evidence/`，正文保留读者做判断所需的最短边界。来源可访问只证明页面存在；hash 变化只证明 bytes 变化；二者都不自动证明正文语义正确或错误。

## 结果

作者需要同时维护正文、测试或实验记录和证据台账。自动检查可以验证结构、链接、标识符、日期与 fingerprint，却不能代替逐 claim 的语义复核；复核者可以是人工，也可以是按 ADR 0004 留下审计记录的 LLM。

## 当前实施说明（2026-09-13）

上述“验证日期与 fingerprint”指的是日期格式、登记关系和已知 bytes 的一致性或变化，不是对来源含义的判断。
`check_content_accuracy.py` 检查编码和来源登记的离线结构；测试、固定样例和实验只支持它们明确写出的输入、实现与结果。
维护者仍须把数学定义、API 契约、测量条件和质量 claim 逐项与相应证据核对，并在正文紧邻写出不能外推的范围。

AI 可以协助找出待核对的 claim、矛盾或可读性问题，也可按 [ADR 0004](0004-llm-source-review.md) 完成有记录的逐项来源复核。它仍不能代替真实读者、授权账号、目标运行环境或独立实验；未留下 claim、证据与处置记录的批量判断不能把来源标为 `verified`。
