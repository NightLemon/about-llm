# ADR 0004：允许可追溯的 LLM 来源复核

- 状态：接受
- 日期：2026-09-20

## 背景

来源 freshness 机制原先只允许人工刷新 `verified`。本项目当前没有可持续的人工作业条件，导致已经逐条阅读、对照正文并留下证据的 LLM 审校仍只能长期显示为待复核。单纯延长日期会掩盖风险，完全拒绝 LLM 复核又会让到期状态失去可执行的恢复路径。

## 决策

`verified` 表示登记范围内的 claim 已完成语义核对，不再暗示复核者一定是人。新的 `review` 对象记录 `method`、`reviewer` 和带锚点的 `record`；`method=llm` 时，来源徽章明确显示“LLM 已复核”。没有 `review` 字段的旧记录按历史人工基线解释。

LLM 复核必须逐来源完成以下动作：

1. 打开当前一手来源，并核对登记的 URL、范围和版本；
2. 找出仓库中全部 `SOURCE:<id>` 标记，逐条判断 claim 是继续成立、需改写、应拒绝还是仍无法判断；
3. 在复核记录中保存直接观察、正文处置和不能外推的边界；
4. 只有继续成立的 claim，或已经同步改正的 claim，才可刷新 `checked_at`、`next_review_at` 与 fingerprint 并保持 `verified`；
5. 无法从公开材料判断、来源冲突或关键证据缺失时，保持 `pending-review` 或改为 `rejected`。

网络探测、批量摘要和“页面可以打开”都不构成上述复核。LLM 也不能把文档字段外推为真实账号可用性、目标 runtime 行为、性能、质量、安全、许可或训练真实性；这些仍需相应环境或独立证据。

## 结果

项目可以在没有人工复核者时继续处理过期来源，同时让读者区分“人工已核验”和“LLM 已复核”。维护成本增加：每个 LLM 结论必须有独立锚点，注册表校验会拒绝缺失记录、未知方法或悬空链接。
