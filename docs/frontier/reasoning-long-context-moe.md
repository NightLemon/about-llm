# 推理增强、长上下文与 MoE

## 推理增强

### 训练时

- 高质量推理示范/SFT：学习问题分解和可验证步骤。
- 结果奖励：只依据最终答案，易获得但信用分配弱。
- 过程奖励模型（PRM）：评价中间步骤，监督细但标注昂贵。
- 可验证奖励：代码执行、单元测试、数学答案或形式证明提供客观反馈。
- 蒸馏：用强模型生成并筛选轨迹训练小模型，可能继承错误与风格。

### 推理时

- Self-consistency：采样多条路径并投票，依赖错误不完全相关。
- Best-of-N：生成 N 个候选，验证器选最好；上限由验证器决定。
- 搜索：树/图搜索探索中间状态，需扩展、评分和停止策略。
- 工具：计算器、代码、检索、证明器把可验证部分外包。
- 反思/修订：根据反馈重写；无新证据的自我反思可能只是更自信。

增加 test-time compute 并非单调提高质量。验证器被 exploit、候选同质、上下文膨胀和错误累积都会使收益饱和。按“每成功任务成本”和风险评估。

## 长上下文

### 扩展方法

- RoPE 插值/频率缩放、继续长序列训练；
- 稀疏/滑窗/块注意力，限制每个 token 的连接；
- 线性注意力或状态空间递推，避免显式 \(T^2\) 矩阵；
- 外部检索、摘要和层次记忆，只把相关信息送入模型；
- KV 压缩、淘汰或量化，降低推理内存。

### 评测维度

上下文窗口标称长度只说明接口接受多少 token。要分别测：单点检索、多针检索、跨段多跳、全局聚合、顺序、冲突解析、长文生成一致性和位置鲁棒性。Lost in the middle 指相关信息位于中间时利用率下降，但程度依模型和任务。

长上下文与 RAG 不是二选一。RAG 降噪并提供权限/更新；长窗口保留更多局部关系。常见组合是先检索文档/章节，再在较长窗口内综合。

## Mixture of Experts

MoE 层包含多个专家 MLP，router 为每个 token 选择 top-k 专家：

\[
y=\sum_{i\in TopK(x)}g_i(x)E_i(x)
\]

总参数量可很大，但每 token 只激活少数专家，因此计算接近较小 dense 模型。共享注意力和其他层仍全部计算。

### 训练挑战

- 路由可能集中到少数专家，需要 load-balancing auxiliary loss。
- 每专家有 capacity，溢出 token 可能丢弃、重路由或增加缓冲。
- 专家并行引入 all-to-all，通信和负载不均可能吞噬稀疏计算收益。
- router 数值稳定、专家初始化和 token dropping 会影响收敛。
- 专家未必对应清晰的人类领域，不能只凭观察命名。

### 推理挑战

虽然激活参数少，所有专家权重仍需驻留或跨节点访问，内存和通信大。小 batch 下 token 难以聚合到专家，硬件利用率可能差。量化、专家缓存和合理并行拓扑很重要。

## 前沿研究的判断框架

面对“新 SOTA”，检查：是否同模型/数据/算力/推理预算；是否包含 test contamination；是否只在少数基准有效；延迟和成本是否报告；消融是否隔离真正贡献；代码、数据和随机种子是否可复现；负结果与限制是否充分。
