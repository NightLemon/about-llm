# 如何使用这套手册

这套仓库同时包含教材、实验、项目和参考资料。它们服务于不同阶段，不应该混在同一次阅读里。

## 先判断你正在看什么

| 页面类型 | 主要问题 | 合适的读法 |
|---|---|---|
| 教材章节 | 机制为什么成立 | 跟随例子推导，完成自测 |
| 实验 | 改变一个变量会发生什么 | 先预测，再运行，再解释差异 |
| 项目 | 多个组件怎样协作 | 从输入输出契约和失败路径开始 |
| 参考资料 | 某个术语、版本或来源是什么 | 按需查询，不必连续阅读 |

项目 README 可能包含较多运行参数；机器可读结果位于 `artifacts/`。第一次学习某个主题时，不需要阅读固定哈希、完整报告或发布账本。

## 一章的推荐读法

1. **明确问题**：这一章要解释哪个现象或解决哪个工程问题？
2. **建立直觉**：先用自然语言复述，不急着背公式。
3. **检查形状**：为张量、集合或状态机标出输入、输出和中间状态。
4. **走完例子**：用最小数字手算一次，或跟踪一条请求的完整路径。
5. **运行实验**：只改变一个变量，并在运行前写下预测。
6. **回答自测**：不能解释失败原因时，回到对应小节，而不是继续堆新概念。

## 怎样使用代码

学习时优先运行页面给出的单个脚本。例如：

```powershell
python projects/transformers-basics/train_byte_bpe.py
```

修改源码后，只运行与改动直接相关的测试：

```powershell
python -m pytest tests/test_tokenizer.py -q
```

不要把完整测试套件当作每次学习或每次文字修改的必经步骤。完整回归属于维护流程；它不能代替对结果的解释，也不应该阻塞一次局部内容修订。

## 怎样记录实验

一份有用的学习记录只需要六项：

```text
问题：我想弄清什么？
预测：运行前我预计会发生什么？
设置：输入、版本、随机种子和关键参数是什么？
观察：原始结果与失败样例是什么？
解释：为什么出现这个结果？
下一步：哪个实验最可能推翻当前解释？
```

避免只写“跑通了”或只保存最终平均分。一个失败样例通常比一张没有上下文的成功截图更有学习价值。

## 怎样读公式和论文

读公式时依次确认：变量含义、形状、单位、可训练量、目标函数和计算复杂度。能用一个两 token 或两文档样例走完计算，才算建立了可操作的理解。

读论文时先看问题、图表、结论和限制，再进入方法细节。把作者报告、独立复现和自己的实验分开记录；不同数据、规模或预算下的结果不能直接横向比较。

## 卡住时怎么办

- 不认识术语：查[术语表](../reference/glossary.md)。
- 看不懂形状或概率：按需回到[数学基础](../foundations/math.md)。
- 环境无法运行：查[环境与硬件矩阵](environment.md)。
- 不知道下一章：看[知识地图](knowledge-map.md)。
- 想把知识变成作品：从[项目索引](../practice/project-index.md)选择一个最小项目。
