# 如何使用这套手册

## 开始导航

- 第一次接触 LLM：先用[新手知识地图](beginner-map.md)自检并完成 30 分钟最小运行。
- 还不知道主题全貌：浏览[完整知识地图](knowledge-map.md)，但不要求一次读完证据台账。
- 已经有学习目标：直接选择[入门、工程或研究路径](learning-paths.md)。
- 准备运行代码：查看[环境与硬件矩阵](environment.md)和[仓库地图](repo-map.md)。
- 想从实践开始：进入[实验与项目](../practice/labs.md)。

## 不要按目录从头背到尾

先选择一个可验证的目标，例如“解释注意力的张量形状”“做一个带引用的 RAG 问答”“让模型稳定输出合法 JSON”。围绕目标阅读，完成实验，再回到知识地图补齐缺口。

推荐循环：

1. **预测**：阅读前先写下你认为系统如何工作。
2. **学习**：阅读直觉、机制与例子。
3. **实现**：不用大型框架或只用最少封装实现关键步骤。
4. **测量**：建立基线，改变一个变量，记录指标与失败样本。
5. **讲解**：用自己的话解释结果；不能解释通常意味着还没掌握。

## 建立学习日志

每次学习至少记录：日期、问题、假设、证据、结论、仍不确定之处。把“我觉得”改写为可以验证的陈述，例如：

- 弱：温度越高越有创意。
- 可验证：在固定模型、提示和 `top_p=1` 时，温度从 0.2 提高到 1.0 会增加多次采样的 token 分布熵和答案差异；任务正确率可能上升也可能下降。

## 如何读公式

先问五件事：每个符号的形状是什么、输入输出是什么、哪些量可训练、优化什么目标、计算/存储复杂度是什么。能用一个 2×3 的玩具张量走完计算，比记住公式更有价值。

## 如何读论文

按“摘要 → 图表 → 结论与限制 → 方法 → 实验 → 附录”的顺序初读。区分：

- 论文真正证明了什么；
- 只在特定数据、模型规模或预算上观察到了什么；
- 作者推测但未验证什么；
- 基线是否公平，指标是否对应真实目标。

## 如何面对快速变化

算法原理相对稳定，模型名称、API 和榜单变化很快。对时间敏感信息记录“截至 YYYY-MM-DD”，不要把单次榜单排名当作永久事实。优先学习可迁移的概念：目标函数、系统约束、评测设计和安全边界。

## 下一步

选择一条[学习路径](learning-paths.md)，完成对应的首个可交付成果；遇到环境问题时回到[环境与硬件矩阵](environment.md)，需要核对当前事实时查阅[内容准确性台账](../reference/accuracy.md)。
