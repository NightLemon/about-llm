# 四周速成：应用工程 + 推理服务

这是一条**为期 20 天、每天约 8 小时**的密集路线，目标只有一个：
用最短时间拿到应用工程（RAG / Agent）和推理服务两个方向的核心工程判断力。

它与仓库既有的[五条学习路径](../learning-paths.md)是**并列关系**，不是替代：
既有路径按角色分、追求完整；这条路径按天排、明确告诉你**什么可以跳**。

**速成导航**：[怎样使用](#how-to-use) · [跳过清单](#skip-list) · [四周概览](#overview) · [完整路径](../learning-paths.md)
{ .doc-nav }

## 这条路线的核心假设 { #how-to-use }

三条，先认同再开始：

1. **原理够用就行，边界必须清楚。** 本仓库每个脚本都有 `scope` 字段，里面写满
   `xxx_executed: false`、`xxx_proved: false`。这些"我没有验证什么"的声明，
   比原理推导更接近真实工作。每天的任务里都会让你读它。
2. **先预测，再运行。** 实验的价值在于你**预测错**的那一刻。先看答案，价值损失八成。
3. **CPU 优先，GPU 攒到最后。** 前 15 天全部可在无 GPU 机器上完成；
   第 4 周集中上 GPU 补齐性能证据。

## 每天怎么用

每个日计划页面结构相同：

| 区块 | 用途 |
|---|---|
| 今日目标 | 一句话说明今天要拿到什么判断力 |
| 时间盒 | 把 8 小时切成 2–4 块，每块有明确产出 |
| 动手 | 具体命令与要预测的内容 |
| 必答题 | 不看笔记能答出来才算过关 |
| 今日交付 | 写进学习日志的东西 |
| 可以跳过 | 明确告诉你今天**不用**看什么 |

进度由"必答题能否答出"决定，不由时间决定。某天超时就顺延，不要为了赶进度跳过必答题。

## 开始之前

确认环境可用（[环境与硬件矩阵](../environment.md)）：

~~~powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -c constraints/ci.txt -e .
~~~

准备一个学习日志文件。每天往里写四样东西：运行配置、原始观察、一个失败样例、自己的解释。
这份日志到第 20 天会直接变成项目报告的素材。
