## 三个必须自己算一遍的地方

### 1. 长度惩罚

归一化分数是：

```text
normalized_score = cumulative_log_probability / generated_length ** alpha
```

实验 0B 给了一张表，`alpha` 从 0 变到 2 时**排名会翻转**。
先自己算 alpha=0 和 alpha=1 两列，再看文档给的完整表。
算错了比看对了有价值。

### 2. 约束解码为什么必须检查整个 token

这是最容易想当然的一点：按首字符过滤词表看起来能工作，
但 tokenizer 的一个 token 可能横跨多个字符，首字符合法不代表整串合法。
实验里有现成的反例，务必自己指出反例中的那个 token。

顺序也是契约：**先 mask 再采样，然后重新归一化**。反过来做会得到一个静默错误的分布。

### 3. 流式停止的重叠规则

当 `BC` 与 `ABC` 在同一字符位置结束时，matcher 取**配置顺序里的第一个**，
不是更长的那个。源码里的匹配逻辑是：收集所有 `endswith` 命中，然后取 `matches[0]`。

这条是**契约，不是最优性结论**。如果你在生产里假设"总是取最长匹配"，
换一个实现就会踩坑。今天要练的就是分清这两类陈述。
