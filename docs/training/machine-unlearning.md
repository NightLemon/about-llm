删除数据库行、清理 RAG 索引、撤销日志和降低训练样本对参数的影响是不同任务。先确定删除对象和系统边界，
再选择从未包含目标数据的重训对照或近似方法；输出过滤只能称为风险缓解，不能自动升级为参数遗忘证明。

## Machine unlearning 不是删除数据库行

删除源数据与消除已训练模型中的影响是不同问题。

### 参考标注（gold standard）对照

条件允许时，从未包含目标数据的数据集重新训练，是最清晰的对照。可以从头训练，也可以从目标数据进入前的安全 checkpoint 恢复。
这种方法成本很高，而且随机训练会产生不同参数，因此应比较行为、攻击成功率和任务质量分布，而不是逐参数相等。

### 近似 unlearning {#142-approximate-unlearning}

近似方法包括反向优化目标、数据影响近似、移除 adapter、模型编辑和蒸馏等。
这些方法可能让常见 Prompt 停止复述目标内容，却仍留下其他可观察影响：改写后可以提取、
membership inference（成员推断）仍有信号，或相关内部表示仍然变化。

### 威胁模型

声明攻击者：

- 只有黑盒 API，还是拥有 logits、权重或梯度；
- 是否知道目标样本和训练算法；
- 可查询次数和 prompt 变体；
- 目标是逐字提取、成员推断、属性推断，还是检测功能影响。

“我们测试的十个 prompt 不再输出”只支持这十个行为，不支持数学意义上的完全删除。

## Unlearning 评价

- 在删除集上执行提取与成员推断攻击；
- 改写、翻译、上下文诱导和相邻样本；
- 保留集（retain set）与通用能力；
- 与从未训练目标数据的重训模型比较；
- 使用多个随机种子、不同攻击强度和置信区间；
- 检查训练与部署工件、缓存、RAG 索引和日志是否同步处置。

若系统只增加了输出过滤，应称为风险缓解，不能写成参数影响已经消除。

## 删除与合规门禁

- replay buffer 和派生数据遵守 retention/deletion；
- unlearning claim 有攻击者与评价范围；
- 无法证明的影响明确标为 unknown；
- 外部 cache、index、日志与备份有单独处置。

## 系统级处置清单

模型之外还要单独处理 replay buffer、派生数据、Adapter、缓存、RAG 索引、日志、备份和已发布工件。
每个位置记录负责人、保留依据、删除结果与无法判断的状态；来源链断裂时保持 `unknown`，不要用一次 Prompt
未复述目标内容代替处置证据。

## 当前证据边界

本仓库没有对目标 LLM 执行重训对照、成员推断或 extraction attack，因此不能声称完成了真实模型遗忘。
本页提供的是威胁模型、对照与验收接口，实际结论必须绑定目标数据、模型、攻击预算和运行结果。

## 自测与实践

1. 为一次删除请求分别列出数据库、RAG、训练集、模型、日志与备份中的对象。
2. 定义 black-box 与 white-box 两种攻击者，并写出各自查询或访问预算。
3. 为什么十个 Prompt 不再复述目标内容仍不能证明完成遗忘？
4. 为删除集、保留集和通用能力设计一次与重训对照的评测。
