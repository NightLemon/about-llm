本页定义教材中的事实如何分类、验证和维护。目标不是用“官方”二字替代证据，而是让读者知道每条结论在什么边界内成立、仓库实际验证了什么、哪些仍需目标环境实测。

## 四类陈述与证据

| 类别 | 典型内容 | 首选证据 | 必须写清的边界 |
|---|---|---|---|
| 数学与算法 | attention 公式、复杂度、KV Cache 容量 | 推导、可执行小例子、单元测试 | 变量定义、单位、假设和省略项 |
| 代码与 API | 请求字段、chat template、CLI 参数 | 固定版本官方文档、schema、契约测试 | provider、API/runtime 版本、`checked_at` |
| 产品事实 | 模型能力、配额、价格、区域和数据政策 | 对应产品的官方页面 | 检查日期；不得把当前状态写成永久事实 |
| 工程估算 | 显存、吞吐、延迟和成本 | 明确公式加目标环境基准 | 硬件、dtype、batch、长度、并发、软件版本和误差来源 |

论文能说明论文中的方法，不能自动证明某个当前闭源产品采用相同内部实现。官方文档能证明文档在检查时给出的接口承诺，也不等于本仓库已经在真实账号、网络、GPU 或付费端点上运行成功。

## 核验边界

- 离线单元测试证明给定输入下的本地实现行为，不证明云端 API 当前可用。
- CPU smoke test 不证明 CUDA kernel、vLLM、bitsandbytes 或目标 GPU 的兼容性与峰值显存。
- 一台机器上的 benchmark 只对记录的 workload 和版本有效，不是普适性能排名。
- JSON mode 只保证产生有效 JSON；OpenAI Structured Outputs 在受支持范围内约束 JSON Schema，但两者都不保证内容真实、业务规则正确或工具调用已获授权。
- schema、引用格式和安全分类器通过，只是系统质量证据的一部分，不能替代语义评测与权限控制。
- Live execution report 必须绑定当次日期与当前 runtime identity；固定离线 verifier 只接受对应的 reviewed artifact identity。依赖升级后的 live 通过不能自动升级旧录制证据，两类报告不可互换。

## 引用证据的五层边界

1. `citation_syntax` 只检查可识别引用、supplied known ID 与段落覆盖；它的复合分数不是 groundedness。
2. source identity/authorization 要绑定实际 tenant/principal/policy/corpus snapshot；case metadata 中的 `citation_sources` 只是 scorer 收到的授权来源声明，不能自证来源。
3. `about-llm.citation-evidence-span-metric.v1` 验证 strict JSON、source membership、零基/end-exclusive Python string offset 与 exact quote。固定 cases/answers 为 1,015/1,138 bytes，SHA-256 `ceb3ff9dc40ae973e07abbb0b5ba0eeb0a07876290a7dbe06021d0d48ff289e8` / `c61507ec49732a67167dc4bef0e57ee3a18c4359c9a91e7f607074959f712661`，五例分数 `[1,0,0,0,1]`。
4. 最后一例让无关 claim 精确引用 `Earth` 而仍通过，锁定“不推断 entailment”的实现边界。语义支持需独立 atomic-claim verdict、judge/人工来源、代表性校准集与误判率。
5. source truth/currentness、答案完整性和 `publish/reject/abstain` 是更外层 policy；任何一层通过都不能借用为下一层结论。Fixture 的 `latency_seconds=0.0` 是非性能占位，不执行模型、ACL 服务或 judge。

## 写作与实现规则

1. 未公开的闭源模型参数量、层数、训练数据、路由和后训练配方保持未知，不从旧论文或同品牌模型外推。
2. 开放权重模型的架构结论绑定 checkpoint revision，以实际 `config`、tokenizer、chat template、generation config、model card 和许可为准。
3. 时间敏感 API 或产品事实记录 `checked_at`；稳定教材不维护“永久 latest”模型、价格或上下文窗口表。
4. 数字示例写明单位、公式和排除项。容量估算与实测峰值分开，decimal GB 与 binary GiB 不混用。
5. 性能结论绑定硬件、dtype/量化、输入输出长度分布、batch/并发、runtime/kernel 版本和采样参数。
6. OpenAI-compatible 只表示部分请求形状兼容；provider 的扩展字段、错误、usage、流式事件和工具语义分别验证。
7. 工具调用是模型提出的候选动作，不是授权。参数校验、身份、权限、幂等和审计由外部 runtime 承担。

## RAG 请求主线的准确性边界

RAG 教材用两个固定请求建立同一条证据链：请求 A 在授权 BM25、recorded rerank、packing 后，
从 `rag-security` 精确抽取带 `[S1]` 的回答；请求 B 虽有三个 topical 结果，lexical coverage 只有 `2/9`，
因此 abstain。可执行 walkthrough、逐 claim oracle 与目标环境缺口集中在
[RAG 请求、回答与拒答证据账本](rag-answer-controls.md)。

正文采用以下限定：

1. `BM25Index` 证明 authorization-before-query-statistics-and-ranking，不声称可信索引进程从未读取隐藏正文。
2. Recorded rerank score 证明 query/chunk/scorer binding 与控制流，不声称 learned model 执行或质量提升。
3. Exact span 与 citation syntax 证明 provenance、known ID 和段落覆盖，不证明来源真实、语义支持或答案完整。
4. `0.55` lexical threshold 只适用于本仓库准备的固定样例；目标域阈值必须用独立 calibration/test split 选择和报告。
5. 固定 Qwen 的原始 `0/2`、policy replay 与 guarded runtime 是三类不同证据，不能相互借用为总体质量、远端调用、GPU/vLLM 或生产安全结论。

## 近期论文快照规则

[近期论文解读](../papers/index.md)与稳定教材分开维护。首期固定 `snapshot_at=2026-08-12`，不静默改写当时的入选依据，并遵守以下边界：

1. **榜单快照**只说明论文在固定 Hugging Face 周榜或月榜中出现，热度不等于质量、正确性或长期影响；页面互动数字若无法明确归属，不进入教材。
2. **预印本**不等于已经同行评审；会议接收状态只有在论文页面明确注明时才记录。
3. **作者报告**不等于独立复现。模型团队 technical report、自建 benchmark、项目 demo 和作者发布 artifact 都保留证据来源标签。
4. **编辑精选**按课程相关性加入，不冒充榜单入选，也不以机构、模型规模或标题热度替代实验设计。
5. **版本冲突**保留冲突口径并降级结论。摘要、正文、项目页或修订版本数字不一致时，不选择更漂亮的数字作为主结论。
6. **不可外推**必须单列：模型、harness、工具权限、数据、硬件、精度、成本、版本和 benchmark 构造至少随结果一起记录。

## 已有可执行证据

- Masked-token gradient accumulation oracle 用整数 probability weights 与 `Fraction` 精确计算 categorical probability、`softmax - one_hot` token-logit gradient 和 micro-batch 权重；ignored token 不进入 numerator/denominator。固定两个 micro-batch 的有效 token 数为 `[1,3]`、ignored positions 为 3：正确 token mean 以 `1/4,3/4` 加权，class-aggregate gradient 为 `(+23/40,-23/40)`；等权 micro-batch mean 以 `1/2,1/2` 加权，得到 `(+7/20,-7/20)`，naive−full 为 `(-9/40,+9/40)`。项目 toy 另真实执行 PyTorch 2.13.0+cpu Float64 `cross_entropy.backward()`：full batch 与逐 micro-batch sum 后除全局有效 token count 的梯度 `torch.equal`，最大绝对误差 0；naive 路径不同，ignored rows 梯度为 0。18 个定向测试覆盖精确值、loss、输入 gate、资源上限、JSON 投影与项目 CLI。该证据只覆盖 authored logits/targets/mask 和单进程 reduction；class aggregation 不是目标模型参数梯度。没有 optimizer/parameter update、dropout/BatchNorm、AMP、DDP/FSDP/ZeRO collective、`no_sync`、CUDA、目标 tokenizer/model/dataset、性能或质量评测，不能证明任意 Trainer/分布式配置、收敛或生产训练正确。
