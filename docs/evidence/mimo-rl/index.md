## 一份公开快照包含什么

每个快照目录恰好包含三个文件，下载时应完整保留目录关系：

| 文件 | 用途 | 阅读顺序 |
|---|---|---|
| `manifest.json` | 快照身份、分项采集时间、覆盖与失败状态、公开文件长度和 SHA-256 | 先看 `status`、覆盖与缺口，再核对文件 |
| `facts.json.gz` | 压缩的数值事实投影：曲线坐标和值、数值状态、必要的运行、指标和评测标识 | 需要逐点分析时离线导出 |
| `viewer.html` | 本仓库原创离线查看器，展示同次投影 | 校验后在浏览器本地打开 |

公开“完整”以当次可发现、可取得的数值范围为分母，并显式排除原站专有材料。
原始 HTTP 响应体、原站 HTML、JavaScript、CSS、说明文案、公告、样本正文与原站截图均不进入公开包、
归档分支或 Actions 上传；需要核查时仅保存在采集机器的私有目录。
公开包不能还原原站全部原始材料，也不覆盖未公开数据、已删除历史或两次采集之间的瞬时状态。

原站材料的再分发许可尚未确认，采集与公开访问均不授予许可。
本仓库的许可只覆盖原创贡献，不自动覆盖第三方事实资料及其可能适用的数据使用条件。
查看器使用本仓库原创展示代码，不附原站截图或应用资源。

## 离线核对与主动采集

命令在仓库根目录执行，支持 Python 3.10—3.12 标准库，无需安装第三方依赖；自动任务固定使用 3.12。
下面的 `SNAPSHOT` 是占位符，需替换为下载或采集得到的完整快照目录。

~~~powershell
python scripts/mimo_rl_archive.py verify SNAPSHOT
python scripts/mimo_rl_archive.py export SNAPSHOT --output outputs/mimo-rl-facts.json
~~~

`verify` 检查当前公开文件及声明范围，不访问上游。`export` 先校验，再导出便于分析的数值 JSON。
导出目标应选择尚不存在的文件，保留旧结果以便比较。
只有取得同次私有材料时，才可额外核对原始响应体；仅下载公开包不能声称已复核全部原文。

主动联网采集使用独立公开与私有根目录：

~~~powershell
python scripts/mimo_rl_archive.py collect --output outputs/mimo-rl-public --private-output artifacts/mimo-rl-private
~~~

`collect` 返回 0 表示采集器报告完整，返回 2 表示已保存部分采集记录；其他非零退出或超时可能没有形成可用快照。
部分记录可以通过文件完整性校验，供审计缺口使用。该校验不把 `partial` 改为 `complete`，
也不把采集成功升级为来源真实性、训练效果或人工语义审核通过。
后续重试形成新快照，保留旧记录中的失败事实。

## 手动采集与以后启用定时调度

[独立归档工作流](https://github.com/NightLemon/about-llm/actions/workflows/mimo-rl-archive.yml)
当前只配置 `workflow_dispatch`，没有 `schedule`、push 或 PR 触发。
推送教材不会自动访问 MiMo 页面；需要新快照时，由维护者在 Actions 页面手动运行。

手动运行前需要满足以下条件：

1. 将工作流、采集器及其公开字段限制合并到默认分支，并确认仓库已启用 GitHub Actions。
2. 当前配置只允许 `NightLemon/about-llm` 的默认分支执行，避免 fork 自动采集；手动运行也选择默认分支。
3. 仓库和组织策略允许归档 job 使用 `contents: write`，允许创建并正常快进更新 `mimo-rl-archive`。
   分支保护或 ruleset 可能阻止机器人创建、提交或推送；应按组织政策授权，不以强制推送绕过限制。
4. 先检查手动运行的三个独立结果：采集状态、全部候选文件校验、持久分支发布。
   同时确认上传物中只有公开包和工作流状态回执。

管理员可在 Actions 页面选择该工作流并使用 **Disable workflow** 停用全部触发。
以后确认需要定时采集时，再向默认分支工作流添加 `schedule`，建议 cron 为 `23 */6 * * *`，对应 UTC 00:23、06:23、12:23、18:23。
同时调整测试中“仅手动触发”的断言，并检查权限与最新运行记录。
GitHub 调度可能延迟或遗漏，实际采集间隔以每份清单为准。停用不会删除归档分支内已有快照。

工作流没有 PR 或 push 联网触发，不参与文档构建 gate；归档失败不会阻止正常教材构建。
它仅在归档 job 授予写权限，串行运行且不取消正在执行的任务，单 job 最多 20 分钟。
采集步骤最多 14 分钟，为校验、发布和备份留出时间；基础设施强制终止仍可能阻止最后的备份步骤。

## 部分采集、发布失败与保存期限

工作流先收集全部候选目录，逐份校验身份、文件清单与完整性，并拒绝未复核展示文案字段。
只有全部候选通过后，才原样复制公开目录；任何候选失败都会阻止整批发布，不在发布阶段修补或重新生成快照。

采集退出 2 时，完整性通过的 `partial` 目录仍追加到持久分支。
工作流在报告采集、校验与发布结果并尝试备份后，以失败状态结束，提醒维护者查看缺口。
同名目录只有内容完全一致才视为重复；内容不同则停止，保留原目录。
并发外部写入或保护规则导致普通快进推送失败时，工作流保留公开备份供人工恢复，不强推或改写旧历史。

Actions 的 `mimo-rl-public-<run-id>-<attempt>` artifact 仅保存通过校验的公开包与状态回执，保留 **30 天**。
没有可用快照时只保存工作流生成的状态回执；原始错误正文和采集日志留在 runner 私有目录，不上传。
短期 artifact 用于诊断与发布失败后的恢复，长期保存依赖上述归档分支。托管 runner 销毁后，私有材料不保证保留。

分支持续增长，维护者应观察快照数量、单包大小、仓库容量、clone 耗时与平台单文件限制。
接近容量限制时先规划额外的持久存储和可追溯迁移，保留旧快照身份与链接；当前工作流不自动删除历史来腾空间。
