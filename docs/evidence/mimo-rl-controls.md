## 公开数值与本地原始材料分开保存 {#publication-policy}

以下规则描述自动采集器生成的三文件快照包。上面的教学截图另存在 `figures/`，不混入历史快照或自动归档输出。

| 材料 | 保存位置与用途 | 公开边界 |
|---|---|---|
| HTTP JSON 响应体原始 bytes | 本地私有目录，用于逐文件哈希和原始字段复核 | 不提交原始响应体 |
| 原站 HTML、JavaScript、CSS 与可取得的页面资源 | 本地私有目录，用于核对当时的展示逻辑 | 不随仓库或站点分发 |
| 整页截图、公告、说明文案与样本正文 | 如需保留，仅限本地核查 | 排除出自动快照包；局部教学引用见上节 |
| 数值事实投影 | 公开 gzip 包，保存曲线数值、坐标、必要技术标识与数值状态 | 按公开字段范围生成，不任意透传文本 |
| 采集与文件清单 | 公开包，记录时间、来源、文件哈希、范围与缺口 | 不含秘密、原始正文或私有绝对路径 |
| 本仓库原创离线查看器 | 公开包，把事实投影画成曲线 | 使用本仓库编写的展示代码，不复制原站代码或页面设计资源 |

原始响应体应按取得的 bytes 保存；把 JSON 解析后重新序列化得到的 bytes，要作为派生物单独对待。
二者可表达相同数值，却未必具有相同文件哈希。

必要的运行、指标、数据来源类别与基准标识用于定位数值。
允许这些技术标识不代表可以公开任意字符串字段，尤其是提示词、回答、公告、错误响应正文或整段 HTML。
未知字段应先记录结构缺口，再判断是否能安全纳入投影。

原站材料的通用再分发许可尚未确认，自动快照包继续排除原站截图、正文和代码。
第三方材料及其权利不因引用、下载或数值投影而获得本仓库 CC BY 4.0 授权；
本仓库只能授权原创贡献，来源权利与可能适用的数据使用条件仍需单独核对。

## 一次采集是一个窗口，不是原子瞬间 {#capture-window}

采集器使用 Python 标准库，按批读取公开接口，减少集中请求。
每个请求保留开始、结束时间、请求对象与结果。当前每个请求只尝试一次，失败后由维护者再次手动采集。
只有一个总时间戳，无法说明一条曲线与一个实时状态之间相隔多久。

每批最多 24 个指标，串行请求之间至少间隔 0.25 秒；每次最多 256 个请求、64 MiB 响应体与 10 分钟采集窗口。
单响应上限为 16 MiB，请求超时最多 20 秒；这些是采集器的停止条件，底层网络强制阻塞仍受工作流超时约束。
9 月 17 日及本次前两份记录仍按当时的 48 项批次保存，不回写旧清单；24 项调整见下方监督记录。

| 接口对象 | 需要保留的观测 | 核对重点 |
|---|---|---|
| `/rl/api/runs` | 可见运行目录 | Pro 与 Flash 分别处理，不假设共用版本 |
| `/rl/api/status` | 采集前后各运行状态 | 比较进度、版本或重启变化 |
| `/rl/api/tags` | 每条运行的完整指标目录 | 作为曲线覆盖分母，保留没有数据的指标 |
| `/rl/api/series` | 各批返回的运行、版本、步数、时间轴及标量值 | 核对请求范围、返回身份与坐标对应 |
| `/rl/api/live` | 实时采样器的可公开数值状态 | 保留状态时间、单位、子集与缺失 |
| `/rl/api/benchmarks` | 每个基准的逐检查点数值结果 | 从结果本身取得检查点关联 |
| `/rl/api/notices` 与原页面 | 公告和展示逻辑的本地核查材料 | 原文不进入公开数值投影 |

这些接口是采集约定中的对象，不构成上游永久兼容承诺。
每条运行分别取得目录和对应曲线版本；分批请求需要保存各自的轴，不能把不同批次按列表位置直接拼接。

如果采集期间发生重启、版本更新或目录变化，要把前后状态与受影响请求一起记录。
当前实现不在同一快照内重试。无法取得一致范围时，结果保留为部分采集，下一次尝试另建快照。

即使采集前后版本相同，也只能说明这些观测没有显示版本变化。实时采样池仍可能持续变化，
因此整包材料始终带有非原子的时间窗口边界。

## “完整”需要先写出分母 {#coverage}

覆盖分母是当次取得的运行与指标目录、请求范围和接口对象。
它不包括上游未公开的训练内部数据、已删除的历史，也不保证两次采集之间的瞬时状态都能被保存。

逐运行、逐指标至少需要区分：

- 目录中存在且取得数值与坐标；
- 目录中存在，但返回空序列或没有当前范围的数据；
- 请求失败、只取得部分批次，或解析失败；
- 返回了新字段或新结构，当前投影尚未支持；
- 版本、步轴或时间轴不一致，尚未形成可比较序列。

空序列是一种观测。请求失败表示未取得证据。两者需要不同记录；
`null`、缺失字段、无法判定与数值 0 也必须分别保留，禁止推断 `null=0`。

“全部已知指标都被请求”与“全部已知指标都有可用数值”是两个检查。
清单同时保留目录规模、已处理范围与缺口，让读者选择能支持自己问题的子集。

benchmark 的缺失同样进入分母。一个检查点只有部分基准返回时，保留已取得的结果，
其余项目记录为未取得或未发布；不得填零，也不得借用邻近检查点的值。

## 文件哈希、版本与横轴怎样核对 {#verification}

公开快照由清单、gzip 数值事实包和原创离线曲线查看器组成。
校验时先核对文件，再核对数据身份和覆盖范围，最后由读者判断指标语义。

| 核对层 | 检查内容 | 可以支持的结论 |
|---|---|---|
| 文件 | 清单列出的文件长度与 SHA-256 | 当前文件与清单绑定的 bytes 一致 |
| 数据结构 | 数值类型、缺失标记、可解析性与支持的结构 | 可以按声明的投影读取这些数据 |
| 曲线身份 | 运行、版本、指标与请求范围 | 该序列没有被混入另一运行或返回版本 |
| 坐标 | 值与步轴、时间轴长度及逐点对应关系 | 当前点保留了声明的横轴身份 |
| 覆盖 | 指标目录、已取得范围、失败与未支持项 | 哪个子集可用，哪个范围仍不完整 |
| 私有原文 | 可选核对匹配私有目录内的原始文件 | 本地原始 bytes 与所记录清单一致 |

检查横轴时，要保留原始步数与时间；重启造成的重复坐标或不同版本需要分别解释。
不能为了让图连起来而补零、平滑缺口、移动点位或合并不同运行。跨版本比较需显式选择并说明范围。

SHA-256 能发现与已知清单不一致的文件变化。任何人若同时改写文件与无密钥清单，都可能形成另一份自洽材料，
所以哈希不认证发布方、采集时间或训练真实性，也不证明再分发权限。

只有公开包时，可以核对公开文件和投影结构。额外提供匹配的本地私有目录，才有条件核对原始响应体。
两种校验范围应分别报告，不把仅有公开文件的核对描述成已审阅原文。

一份部分采集的文件可以全部哈希一致。文件校验成功与覆盖完整分别记录，引用时两者都要查看。
`verify` 也不运行 MiMo 模型、重新执行 benchmark 或决定某项训练方法是否有效。

命令中的尖括号内容是占位符：快照参数应替换为下载后的本地目录，私有目录的 ID 应与同次采集匹配。

### 主动联网采集

~~~powershell
python scripts/mimo_rl_archive.py collect --output docs/evidence/mimo-rl/snapshots --private-output artifacts/mimo-rl-private
~~~

这一步访问上游，公开投影与私有原始材料分别写入不同根目录。
每次采集使用独立身份；发生失败时保留失败报告与已经取得的范围，后续重试另存新记录，避免覆盖旧快照。
私有材料仅保存在采集机器本地，不上传到归档分支或公共构建产物。

### 离线核对

~~~powershell
python scripts/mimo_rl_archive.py verify "<snapshot>"
python scripts/mimo_rl_archive.py verify "<snapshot>" --private-root "artifacts/mimo-rl-private/<id>"
~~~

第一条只使用公开包；第二条适用于你持有同次采集私有材料的情况。
保存实际输出，分别读取文件、结构、覆盖与版本一致性结果，不预先把命令执行结束当作完整采集。

### 导出便于分析的事实数据

~~~powershell
python scripts/mimo_rl_archive.py export "<snapshot>" --output outputs/mimo-rl-facts.json
~~~

导出用于读取数值、手工对账和后续分析，不恢复原站页面、样本正文或 MiMo 训练环境。
首次学习可先使用快照自带的原创离线查看器，再选一个点与导出结果核对。

## 手动追加与失败处理 {#scheduled-archive}

当前按维护者要求关闭定时触发，只保留 `workflow_dispatch` 手动入口。
运行后将公开快照追加到 `mimo-rl-archive` 分支，不自动修剪历史。
触发任务、执行成功、取得完整覆盖与完成人工复核是四种状态，应各自查看相应记录。
后续若启用每 6 小时采集，调度延迟、网络中断与上游结构变化仍可能使实际间隔更长。

当前采集只出现在显式手动联网路径。推送不会自动采集；PR 检查继续使用离线材料，网络可访问性不成为 PR 的确定性门禁。
自动任务不修改来源的人工审核结论，也不会自动写入 `verified` 或刷新人工核对日期。

| 失败或变化 | 需要保留什么 | 后续动作 |
|---|---|---|
| 超时、限流或 HTTP 错误 | 接口、时间、单次尝试状态与缺失范围 | 保留部分记录，下次手动采集再尝试 |
| JSON 或字段结构变化 | 受影响接口与结构缺口；原文仅本地保存 | 人工检查投影规则，新增兼容前保持待复核 |
| 采集中版本或横轴不一致 | 请求与返回版本、前后状态、受影响批次 | 停止跨版本拼接，另次采集再核对 |
| benchmark 只返回部分项目 | 已有检查点结果和未取得项目 | 保留原关联，等待后续新快照 |
| 文件缺失或 SHA-256 不符 | 具体文件与校验失败项 | 暂停依赖该文件的引用，不修写旧清单掩盖变化 |
| 原站材料许可不明确 | 本地来源记录与公开排除范围 | 自动快照继续排除截图、正文和代码；局部教学引用单独记录 |

失败记录帮助解释历史缺口。如果一次任务尚未生成可读取的快照清单，任务失败报告应明确“没有可用快照”，
不能把空目录作为成功记录。后续成功只补充新的观测，不改写此前失败的事实。

分支的只追加约定有助于保留历史，但本身不提供密码学不可变性。
长期引用时同时保存快照身份、所下载版本与文件哈希；不要只引用会继续前进的分支顶端。

## 哪种证据支持哪句话

| 结论 | 判定依据 | 仍需独立证据的部分 |
|---|---|---|
| 两题例子的 `avg@4=1/2`、固定候选集 `pass@4=1` | 教材明示的 8 个标签与手算 | 真实题集与采样协议是否有代表性 |
| 图解中的首尾涨幅、末步回落与截图统计 | 单指标 CSV 的逐点算术，以及原站图表截图 | 各步题目组成、变化原因与独立模型能力 |
| 某曲线点为特定数值 | 快照运行、版本、坐标、分项时间与数值投影 | 原发布方测量是否准确 |
| 某分数属于某检查点 | benchmark 逐项结果的原始关联 | 独立重跑、数据隔离与评分有效性 |
| 数据组成使用消费与重启结转口径 | 当次展示逻辑与相关计数核对 | 真实逐样本消费与优化提交账本 |
| 某次采集覆盖声明的公开范围 | 完整目录、请求结果与缺失报告 | 未公开、已删除或采集间隙的数据 |
| 文件与清单匹配 | 文件长度与 SHA-256 对账 | 来源认证、许可、真实执行或因果解释 |

#### 定期采集的处理

- 每次分别读取训练目录、status、live、benchmark 与公告；训练版本未变也不跳过其他接口。
- 保留新鲜度时间字段，完整性与日志年龄分开报告；没有设置自动判停阈值。
- 保留不可覆盖的旧记录；协议标签或同检查点分数变化需要单独说明，不做跨版本静默合并。
- 定时触发继续关闭，仅保留人工入口；本轮没有触发远端采集。

原先设想的六小时间隔适合粗粒度存档，会漏掉分钟级评测发布。是否缩短间隔由学习目标决定，访问更频繁不能让原站产生更新。

## 复核练习

1. 选一个指标，分别指出其目录项、数值、横轴和接口采集时间。
2. 找一个缺失项，说明它是空返回、未发布、请求失败还是解析缺口；为何不能填成 0？
3. 找一个 benchmark 分数，只用结果关联确定检查点，再检查公告是否与之相符。
4. 在副本上改动一个文件，比较校验输出；随后说明为什么重算哈希仍无法认证来源。
5. 写出一句可引用的观测和一句待检验的假设，列明两者需要的不同证据。

维护核查与读者练习分开：读者只需完成[教材的三道读图题](../models/mimo-rl.md#reading-exercise)。
更新材料时，再按[内容准确性规则](../reference/accuracy.md)核对结论和支持材料。
