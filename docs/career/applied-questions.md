## 多模态与对话状态

### 31. 一张图片怎样变成模型的输入？成本从哪一步开始？

**30 秒回答**：常见做法是把图像切成互不重叠的小块（patch），每块展平后投影成一个向量，再加上位置表示。
若图像为 \(H\times W\)，块边长为 \(P\)，可整除时块数是 \(N=\frac{H}{P}\frac{W}{P}\)。
但要注意，**成本从媒体解码就开始了**，不是从语言模型的前向计算开始。

**展开时说明**：

- patch size 不变时，把 224×224 提到 448×448，宽高方向块数都翻倍，总 patch 数约变四倍。
- **原始 patch 数不等于最终视觉 token 数**。模型可能用 pooling、resampler、token merging 或一组查询向量压缩视觉特征。
- 服务商口径的 "image token" 是**计费与容量契约**，可能已包含 resize、tiling 或特征压缩，既不等于原始 patch 数，也不能跨模型比较。

**边界**：不能只用图片尺寸和 patch size 推断上下文成本。要读目标模型的 processor 与架构，记录实际生成了多少视觉 token，
并分阶段记录解码、缩放切块、视觉编码、连接、首轮计算和逐 token 生成的耗时，才知道优化作用在哪。

**缓存追问**：媒体特征缓存的 key 至少要区分租户和可见权限，并包含预处理版本、编码器与模型版本、媒体内容身份。
缓存条目还需要过期和删除机制，否则权限变化或用户删除原图后仍会返回旧特征。

### 32. CER 为什么可能大于 1？两个 IoU 数字在什么条件下才能比较？ { #multimodal-metrics }

**30 秒回答**：\(CER=\frac{S+D+I}{N_{reference}}\)。分母是参考文本长度，而插入错误 \(I\) 不受它约束，
所以插入很多时 \(S+D+I\) 可以大于参考长度，CER 大于 1 是正常的，不是计算 bug。

**可以现场验证**：

```python
from about_llm.evaluation import character_error_rate
character_error_rate("a", "abbbb")  # 4.0
```

**必须先固定的口径**：

- **CER**：Unicode、空白、大小写和标点的处理方式；分母按 Unicode 码点、用户感知字符还是词计数。
  单位不同的数字不能放进同一张表比较。空 reference 的分母未定义，应作为单独 case 处理。
- **IoU**：坐标系。用连续坐标时 `(0,0,2,2)` 的面积是 4；把坐标当作**包含端点的整数像素**时面积公式不同。
  比较前应用已知 box 检查预处理的 inverse transform。
- **Temporal IoU**：帧率是否可变、timestamp 怎样取整、区间端点是否包含。

**怎样验证**：`python -m pytest tests/test_multimodal_metrics.py -q`。
面试时的关键不是背公式，而是先问"这两个数字是不是同一个口径算出来的"。

### 33. 怎样证明模型真的看了图片，而不是靠语言先验猜中？

**30 秒回答**：单看准确率无法区分。要按由弱到强加入对照：无图基线 → 去掉 alt text/OCR/文件名/metadata 的旁路 →
自然反事实（布局相似、金额不同的真实样本）→ 局部反事实（只改一个关键数字）→ 证据定位（claim 是否指向正确 region）→
多切片复现。

**结论怎样表述**：输出随图中目标值稳定变化，说明**视觉模态影响了行为**，但这还没有定位内部神经机制。

**边界**：极端遮蔽可能制造训练分布外的输入，所以自然反事实要与多种 ablation 配合。
视频还有额外陷阱——抽帧会产生 sampling aliasing，瞬时动作或快速闪过的文字可能恰好落在所有采样帧之间；
若 benchmark 答案能从字幕直接得到，纯文本模型也能取巧，模态使用实验应去掉字幕并改动关键画面。

**报告方式**：把对象存在性、关系、计数、属性、文字识别和无答案分别报告，再单独看模型是否表达不确定性。
这样才能区分"没有看清"和"看清后仍然编造"。

### 34. 被叫作"记忆"的其实是三种东西，混淆会怎样出错？ { #memory-taxonomy }

**30 秒回答**：至少要拆成原始对话（transcript）、任务检查点（task checkpoint）和长期记忆（long-term memory）。
三者的用途和生命周期都不同，混在一起会让系统用过期信息代替权威状态。

| 信息 | 主要用途 | 生命周期 |
|---|---|---|
| 原始对话 | 回看双方说过什么 | 按会话与隐私策略保存 |
| 任务检查点 | 恢复尚未完成的工作流 | 任务结束后归档或清理 |
| 长期记忆 | 未来会话减少重复设置 | 可查看、更正、删除，受同意和过期约束 |

**典型分类**："用户偏好中文"可能适合长期记忆；"测试刚跑到第 37 个"属于任务检查点；
**"支付服务已退款"两者都不是**——它必须重新查询权威系统。模型在旧消息里读到一句话，不能替代数据库或工具的当前状态。

**边界**：摘要负责导航，结构化状态负责恢复。摘要会丢掉否定、时间、说话人和不确定性，
所以长任务仍要保留原始事件指针。向量检索适合找到可能相关的旧内容，但**不能决定当前权威状态**——
余额、订单、权限、审批和发布阶段都应从各自的权威系统重新读取。

**检查点的防串线**：租户、用户、任务编号、代码版本和策略版本必须进入读取条件，
不能先加载所有任务再让模型决定哪条属于当前用户。

### 35. 长期记忆由谁决定写入？用户改主意后怎样修正？

**30 秒回答**：模型可以**提出**候选记忆，真正写入应由确定性规则或用户确认决定。
修正用不可变事件加取代关系表达，而不是原地覆盖旧值。

**写入前先回答**：未来用途是什么，用户是否预期，信息是否敏感，来源能否验证，何时过期。
每条记录至少保存值与类型、来源事件、租户/用户/会话作用域、创建更新过期时间、置信度与同意或策略版本，
以及它取代或撤回了哪条旧记录。

**仓库参考实现**：`ConversationMemoryLedger` 把事实和修正保存成不可变事件。
`correct_fact` 不覆盖原记录——旧事实保留在历史中，新事件明确指向它，当前视图只返回新值。
这样既能回答"现在使用什么"，也能解释"为什么发生变化"。它还检查：

- 同一租户、用户和 Key 只有一个当前值，修正必须指向旧事实；
- 修正与撤回不能跨租户或用户；
- 档案作用域必须带同意凭据，会话事实不会自行升级；
- 过期后不再进入当前视图，所有时间必须带时区；
- 未来发生的修正不会提前改变过去时间点的视图；
- 写入值变成规范 JSON 快照，调用方后续修改原对象不会篡改历史。

**怎样验证**：`python -m pytest tests/test_conversation_memory.py -q`。
长会话评测还要覆盖用户中途纠正、打断后恢复、工具报错没被总结成业务事实、外部结果未知时先查询、
删除请求怎样传播，以及租户切换不会检索到别人的记录。

## 产品、发布与治理

### 36. 为什么"模型版本没变"不足以说明这是同一次发布？ { #release-identity }

**30 秒回答**：一次 LLM 应用发布至少由五层共同定义——代码与构建、模型层、上下文层、工具层、运行层。
只锁定模型，其余四层任何一层变化都会改变结果。

| 组成 | 必须绑定的身份 | 只漏掉这一项会怎样 |
|---|---|---|
| 代码与构建 | Git 提交、依赖锁文件、镜像摘要 | 无法确认线上二进制来自哪份源码 |
| 模型层 | 模型、tokenizer、模板、量化版本 | 同名模型仍可能用不同输入格式或数值路径 |
| 上下文层 | Prompt、示例、语料、索引、检索器 | 模型不变时答案仍因证据变化 |
| 工具层 | 工具 Schema、权限策略、审批规则 | 同一参数可能获得不同执行权限 |
| 运行层 | 生成配置、Runtime、路由 | 采样、重试、缓存和备用路径无法解释 |

**关于指纹的边界**（这是追问最容易翻车的地方）：仓库的 `artifact_fingerprint` 把 JSON 组件按稳定字段顺序编码再取 SHA-256，
映射字段换插入顺序指纹不变，消息序列顺序变化则指纹改变。但**指纹只绑定清单里真正列出的内容**——
清单漏掉工具策略时，再稳定的哈希也识别不出策略变化。它也不证明远程供应商执行了哪份模型；
远程执行身份需要供应商回执或请求记录。

**怎样验证**：`python -m pytest tests/test_llmops.py -q`。
这道题问的是发布**由什么组成**；若面试官转向"同一发布为什么仍不可逐字节重放"，那是[另一层问题](interview-questions.md#replay-identity)。

### 37. 回滚为什么不能消除已经发生的错误？

**30 秒回答**：**回滚改变未来，补救处理过去**，是两件事。切回旧版本只影响后续请求；
已经发生的重复退款仍然存在于支付服务中，需要查询权威状态、对账、通知用户并执行前向修复（forward fix）。
这属于事件响应，不是普通发布回滚。

**展开时说明**：一次回滚可能要同时切回代码与镜像、模型/tokenizer/模板、Prompt 与生成配置、
语料索引检索器**以及缓存失效**、工具 Schema 与权限策略。漏掉缓存失效，旧结果会继续被命中。

**缓存与备用路径的边界**：

- 语义缓存可能把措辞相似、但**权限、金额或否定含义不同**的请求合并；退款这类高风险操作不能只靠向量相似度复用结果。
- 失败或空结果应设置较短且有依据的过期时间，避免短暂故障被长期固化。
- 备用模型可能使用不同 tokenizer、工具协议和安全能力，**它本身就是另一条发布路径**，需要独立评测、监控和 Trace。
- 供应商 429、工具超时、检索失败、Schema 无效、安全分类器不可用和 GPU OOM 需要各自的策略，不能共用一句"自动切换"。

**结果未知时**：不要盲目重试。先用稳定业务效果编号查询远端，确认没有应用再决定重放，确认已应用则修复本地状态。

### 38. 模型输出的"我有 97% 把握"能不能展示给用户？ { #calibration-product }

**30 秒回答**：不能直接展示。语言模型生成的"97% confident"通常不是经过任务校准的概率。
可展示的是有无检索证据、claim 是否被 source 支持、多来源是否冲突、结构与业务规则是否通过、
verifier 在固定数据上的校准结果，以及系统是否转入 abstain 或人工复核。

**有拒答能力的系统怎样报指标**：不能只报准确率。对阈值 \(\tau\) 同时记录

\[
\mathrm{coverage}(\tau)=\frac{\#\text{accepted}}{N},\qquad
\mathrm{risk}(\tau)=\frac{\#\text{wrong among accepted}}{\#\text{accepted}}.
\]

提高阈值通常减少覆盖率，所以**"错误率下降"可能只是拒答更多**。产品决策要同时约束覆盖、风险、升级容量和群体切片。

**校准指标自身的边界**：仓库的 `binary_calibration` 用等宽分箱，区间是 `[lower, upper)`，概率 1 归入最后一箱，
空箱不计入。**ECE 是描述性的，依赖所请求的分箱方案**——同一组预测换一个 `bins`，ECE 就会变：

```python
from about_llm.evaluation.calibration import binary_calibration
labels, probs = [1, 0, 1, 1], [0.9, 0.8, 0.6, 0.4]
binary_calibration(labels, probs, bins=5).expected_calibration_error  # 0.425
binary_calibration(labels, probs, bins=2).expected_calibration_error  # 0.225
```

所以报 ECE 必须同时报分箱方案，否则两个数字不可比。`risk_coverage_curve` 则是 tie-aware——
同一置信度的样本整体接受，不会因为排序先后被拆开。

**怎样验证**：`python -m pytest tests/test_calibration_metrics.py -q`。
即使概率经过校准，它也只对指定数据、标签和版本成立，分布漂移后需要重新验证。

### 39. 用户要求删除一条数据，要沿哪条链传播？ { #deletion-propagation }

**30 秒回答**：删除不是删掉一行数据库记录。一次请求可能沿这条链传播：

```text
原始文档 → 解析副本 → embedding → 检索索引 → cache → 日志/回放 → 微调数据 → backup → 第三方副本
```

每个箭头都要有负责人、时限和完成证据。

**最容易被忽略的三点**：

- **去重会让删除失效**。仓库的 `analyze_training_data_lineage` 显示：删除只有在被删项**恰好是 dedup cluster 的 canonical**
  时才会移除 placement 并触发 shard 重建；若 cluster 里还有存活成员，数据实际上没有离开数据集。
  该实现把这种情况标为 `review-surviving-members`，并明确设置 `automatic_canonical_replacement_allowed: False`——
  **换一个 canonical 顶上是需要人工判断的决定，不能自动完成**。
- **已经进入权重的影响不能靠删库行消除**。能撤销到什么程度要按[持续学习与机器遗忘](../training/continual-learning.md)说明。
- **供应商返回的不可读 reasoning 或 signature block 是单独的数据类别**。要知道谁能再次处理它、绑定哪个用户会话和模型版本、
  是否允许重放。只删除可见文本不能证明原始轨迹已脱敏。

**怎样验证**：`python -m pytest tests/test_training_data_lineage.py -q`。
注意该实现自己声明的边界：它验证一张已声明的血缘图并计算哪些 manifest、shard、run 和 checkpoint 与删除请求相关，
但**不执行删除、不认证源记录、不判断镜像能否复用、不从权重中移除信息，也不建立法律合规**。

**退役追问**：换了新模型却继续使用旧索引和后台任务，旧系统实际上并没有退役。

### 40. 总体准确率很好，为什么仍可能对某个群体系统性失败？

**30 秒回答**：总体分数回答不了"谁在承担错误"。一个小群体可以被系统持续漏掉，而总体均值几乎不动。

**审查时至少要问**：

- "正确答案"来自独立准则，还是**直接复制了可能包含历史偏差的旧决定**；
- 对合格对象而言，漏选率是否因语言、格式、路径或其他相关群体明显不同；
- 各切片有多少样本、区间多宽——**"没有显著差异"是否只是数据太少**；
- 多个属性交叉后是否出现单维平均看不见的问题；
- 成本、响应时间、界面和申诉渠道是否让某些人更难获得同等服务。

**边界**：公平不等于强迫所有群体拥有相同平均分。任务标签、错误代价、数据覆盖和救济能力要一起看。
高影响决定还需要可理解的理由和人工复核；**模型事后生成的一段"自我解释"不能当成真实决策因果**。
为测量差异而收集敏感属性时，本身也需要明确目的、保护措施和合法依据。

**与第 24 题的区别**：[第 24 题](interview-questions.md#slice-regression)问的是发现切片回归后怎样做发布决策；
这道题问的是**怎样先让这类回归可见**，以及总体指标为什么不会告诉你。
