# 岗位路线与求职地图

## 常见岗位

### LLM 应用开发工程师

核心能力：Prompt/structured output、RAG、Agent、API/后端、数据库、评测、可观测和安全。面试会追问失败模式、权限、延迟与成本，而不只问框架 API。

### LLM/算法工程师

核心能力：Transformer、训练目标、数据、SFT/PEFT/偏好优化、PyTorch、分布式与实验设计。需要读论文并把结论转为公平实验。

### 推理/系统工程师

核心能力：GPU/内存层次、kernel、KV Cache、批处理、量化、并行、调度与性能剖析。能从 TTFT、TPOT 和吞吐判断瓶颈。

### 评测与数据工程师

核心能力：数据采样与标注、统计、benchmark、错误 taxonomy、judge 校准、数据污染、发布门禁和线上实验。

## 能力证据，而不是关键词

| 能力 | 弱证据 | 强证据 |
|---|---|---|
| RAG | “使用 LangChain” | 分层评测、召回消融、引用验证、ACL 测试 |
| Agent | “多 Agent 协作” | 状态机、幂等恢复、预算、注入与副作用测试 |
| 微调 | “完成 LoRA” | 与 Prompt/RAG 基线比较、回归、显存和数据卡 |
| 推理 | “部署 vLLM” | TTFT/TPOT/吞吐曲线、容量模型与压测 |
| 评测 | “准确率 90%” | 数据来源、置信区间、切片、错误分析和门禁 |

## 推荐学习顺序

1. 能从零解释并实现 attention、causal mask、loss 和 generation。
2. 熟练 PyTorch 张量、训练与调试，读懂 Transformers config 与 model output。
3. 完成一个可诊断 RAG，先不用框架，再接框架 adapter。
4. 做 LoRA/QLoRA，与 Prompt/RAG 基线和通用能力回归比较。
5. 用 vLLM 或等价服务做压测和容量规划。
6. 构建有副作用保护的 Agent。
7. 把全部项目接入统一评测与发布门禁。

## 面试准备结构

- **概念题**：解释机制、公式直觉与边界。
- **代码题**：张量操作、attention、采样、检索指标、并发与缓存。
- **实验题**：如何证明一个改动有效，怎样排除污染和不公平基线。
- **系统设计**：给业务目标与流量，设计 RAG、Agent、服务或评测。
- **故障排查**：召回下降、OOM、尾延迟、Agent 重复执行、线上漂移。
- **项目深挖**：任何数字都要说清数据、基线、指标、环境和取舍。

后续面试题库会按“问题 → 优秀回答结构 → 追问 → 常见误区 → 最小实验”编写，避免背标准答案。

## 简历项目标准

一个项目控制在 3–4 条 bullet：

1. 场景、规模和约束；
2. 你设计或实现的关键机制；
3. 相对什么基线提高什么指标；
4. 可靠性、安全、延迟或成本的工程结果。

不要写无法解释的“准确率提升 30%”。保留代码、配置、评测数据说明、曲线和设计文档，面试时可以从任一数字下钻。
