# 简历项目与作品集

## 项目不是技术名词清单

面试官需要确认你能定义问题、建立基线、做公平实验、处理故障并解释数字。作品集至少提交：

- 架构与信任边界；
- 数据说明和可运行配置；
- 原始评测结果与错误分类；
- 性能曲线和容量假设；
- 测试、CI 和复现命令；
- 已知限制与下一步。

## 项目一：可诊断企业 RAG

**问题**：多租户文档问答，要求引用、更新和 ACL。

**工作**：结构切分、BM25+dense、RRF、rerank、引用验证、蓝绿索引和 tenant-aware cache。

**可写指标**：Recall@5、nDCG@10、引用 precision/recall、无答案准确、ACL 负例、p95、每成功答案成本。

**简历句式**：

> 面向 X 类文档和 Y 条评测查询，构建 BM25+dense+reranker 的多租户 RAG；相对 BM25 基线将 Recall@5 从 A 提升到 B，同时通过 N 条跨租户 canary 测试；在输入 P50/P95 为 M/N token 时将端到端 p95 控制在 T。

所有字母必须替换为可复现数字。不要只写“提升检索准确率”。

## 项目二：可恢复工具 Agent

**问题**：Agent 创建工单/发送消息，不能重复执行或越权。

**工作**：显式状态机、schema、审批令牌、幂等 ledger、预算、故障恢复、注入测试和 trace。

**指标**：任务成功率、平均步骤、参数合法率、重复副作用为零、注入攻击阻断率、恢复成功率和 p95。

**面试证据**：演示进程在工具调用后崩溃，恢复后查询 ledger 而不重复执行；展示同 call_id 换参数被拒绝。

## 项目三：单卡微调与推理

**问题**：在固定消费 GPU 上提高结构抽取或领域格式能力。

**工作**：Prompt/RAG 基线、assistant-only loss、LoRA/QLoRA、checkpoint、回归集、量化、vLLM 服务和压测。

**指标**：任务 F1/格式率、通用回归、峰值显存、训练时间、adapter 大小、TTFT/TPOT/吞吐与每千任务成本。

**关键取舍**：解释为何选择微调而不是只加 Prompt，rank/target modules 如何消融，4-bit 对质量和性能有什么实际影响。

## 项目四：模型评测平台

**问题**：Prompt、模型、索引与工具升级缺少统一门禁。

**工作**：JSONL schema、case/slice、runner、配对 bootstrap、judge 校准、报告和 CI gate。

**指标**：人工一致性、judge precision、回归检出率、评测耗时/成本、发布阻断与线上事故关联。

## 常见扣分项

- 声称使用“大模型”却说不清 model id、revision 和 Prompt。
- 只报最好结果，不报基线、样本量、方差和失败案例。
- 把框架名当核心贡献。
- 在测试集上反复调参。
- 把本地 demo 描述成高并发生产系统。
- 写 99% 准确率却不能定义标签和类别分布。
- 没有处理密钥、权限、日志、重试和删除。

## 面试前自查

对简历每个数字都能回答：数据从哪来？样本量？基线？公式？硬件？模型版本？置信区间？失败分布？若重做会改什么？若不能，删掉或补证据。
